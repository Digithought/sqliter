# The Lens Prover

> **Stability: Experimental** — see [Stability Tiers](stability.md#tiers).

What `proveLens` checks when a logical schema is deployed against a basis: the two roles a logical constraint can play, the coverage checklist that discharges the lens laws, every `lens.*` diagnostic code with its severity, and the acknowledgment and escalation governance over the advisory ones. A satellite of [Lenses and Layered Schemas](lens.md).

## Proving the spec and the body agree

Because the logical spec and the lens body are authored (or generated) independently, the lens layer **proves they agree**. Each constraint in the logical spec plays one of two roles, decided by whether the lens body already guarantees it:

- **Body proves it** → the spec entry is a *proof obligation* (a completeness check). It contributes keys/FDs to the optimizer at zero enforcement cost. Example: the spec declares `unique(x, y)` and the body is `group by x, y`, or `select * from t` where basis already guarantees it. The primitive that discharges this class is `proveEffectiveKeyUnique` ([Effective-key proving](optimizer-fd.md#effective-key-proving-body-proves-it)): it proves the compiled body's *output* relation is unique on the logical key columns via the body's effective key (FD closure). The lens prover owns the logical-column → output-column mapping and feeds the output-column indices to the primitive. This proves a property of the *derived* relation — it is **not** a base-table covering structure (see [Derived-Row Constraints § Covering structures](mv-constraints.md#covering-structures)).
- **Body does not prove it** → the spec entry is an *enforced boundary constraint*, per [Constraint Attachment](lens.md#constraint-attachment).

These proof obligations are the lens laws restated in Quereus's own terms. **PutGet** ("the mapping loses no logical guarantee") and **GetPut** ("round-tripping basis through the lens is faithful") are exactly the cross-checks that the compiled view's inferred FD / key / domain surface conforms to the logical spec. The two laws bind the two directions, and the [coverage checklist](#coverage-checklist) discharges each: `get` preserving the logical guarantees is *column coverage* plus *type/nullability conformance* plus *constraint realizability*; `put` faithfully reaching storage is *key reconstructibility* plus *round-trip*. A lens that satisfies the first group but not the second is readable yet not faithfully writable — the prover reports the uncovered write paths rather than presenting the relation as updatable. The prover is a consumer of the same key-inference surface the optimizer uses; what it cannot prove, it reports — it never silently assumes coverage.

## Coverage checklist

`proveLens` runs in the lens compiler's compile-first loop, per logical table. Every diagnostic is **coded** (the `lens.*` codes below, a stable vocabulary) and **sited** (`{ table, constraint?, column? }`). Errors aggregate across all tables and throw atomically (before any catalog mutation, preserving the atomic-deploy contract); warnings attach to the deploy report. The prover derives no new inference — it applies the existing inference surface (`proveEffectiveKeyUnique` / `keysOf` / `isUnique` / the FD framework) per logical aspect, and degrades to the safe verdict (no spurious error) when a fact cannot be established.

Each check has a severity: an **error** blocks the compile (the mapping is unsound or incomplete); a **warning** is advisory (the mapping is correct but suboptimal). One nuance: **key reconstructibility is reported as a warning** — a non-reconstructible PK does not block the deploy (reads still work); it makes the table read-only and any *mutation* errors at the lens boundary. A PK column is key-reconstructible when it is either a **bare invertible projection** (a written value maps straight back to a basis column) **or** an **authored** (`with inverse`) column whose forward/inverse pair the round-trip enumeration proved a **bijection** (the same `{proved, injective}` verdict that suppresses `lens.getput-lossy`) — a bijection maps a written logical key to exactly one basis key and back. So a PK over a proven-bijective authored inverse deploys **writable**; the non-injective (lossy) authored case stays read-only, and a computed/opaque PK column with no write path stays read-only.

**Errors — the logical surface is not fully realized:**

| Check | Failure |
|---|---|
| **Column coverage** | Every logical column resolves to a basis expression (override or generated gap). An uncovered column errors, naming the column. |
| **Type / nullability conformance** | Each mapped column's basis-derived type and nullability satisfy the logical declaration. A nullable basis expression under a `not null` logical column errors unless a total default or guard supplies a value. A column is `not null` only when *declared* so (or via the session default / an explicitly-declared PK): a no-PK logical table's **synthesized** all-columns key does not force its columns NOT NULL, so a nullable logical column over a nullable basis is sound and deploys clean. **Capability-gated demotion:** when every basis table the body reads declares `permitsGrandfatheredNotNullViolators` (mixed-module bodies stay strict), `lens.nullability-mismatch` demotes to a warning — see the Warnings row. |
| **Constraint realizability** | Each logical constraint is either *proven* by the body or *attachable* as an enforced boundary constraint. A constraint that is neither — e.g. one referencing a column whose lineage is `computed` (no write path) — errors (`lens.unrealizable-constraint`). **Exception — a logical `unique` over a proven-bijective [authored inverse](lens.md#computed-and-generated-columns)** *is* realizable: the bijection gives the authored column a sound write path, so the UNIQUE classifies `proved` by **bijection transport** when the put-target basis column is a declared basis key, else `enforced-set-level` `commit-time` — the O(n) count scan runs over the **logical forward image** and emits `lens.no-backing-index` (not the hard error). Only a **non-bijective** (lossy) authored column — or a computed/opaque column with no write path — still reds `lens.unrealizable-constraint`: uniqueness over a value with no proven write path is neither provable nor enforceable. (A PK over such a column makes the table read-only rather than erroring; see the key-reconstructibility note above.) |
| **Round-trip (lens laws)** | `lens.non-invertible` — GetPut / PutGet hold over the writable fragment, **computed at deploy** from the predicate-honest complement ([Round-Trip Laws § The predicate-honest complement](vu-roundtrip.md#the-predicate-honest-complement)). For a column the lens presents as **writable** whose round-trip cannot be proved faithful, it errors, naming the operator/column (the same diagnostic surface as [view updateability](view-updateability.md#diagnostics)). It **also** errors for an opaque/read-only column the author declared writable via `quereus.lens.writable = true` ([Computed and Generated Columns](lens.md#computed-and-generated-columns)) — the asserted intent turns a silent read-only admit into an authoring error. |
| **Authored-inverse PutGet** (`lens.putget-violation`) | For a column written through an [authored inverse](lens.md#computed-and-generated-columns), PutGet is checked **by composition**: when the logical column carries an enumerable CHECK `in (...)` domain (≤ 64 values, intersected/filtered through the column's other recognized domain CHECKs), `forward(inverse(v))` is const-evaluated per domain value — never a vtab read. A value that fails to reproduce errors, sited at the column and naming the written value and what it reads back as: a put that loses the written value is never acceptable. No enumerable domain, or a composition the const evaluator cannot fold (subquery, volatile function, multi-column `new.*` inverse, multi-source body), degrades to the safe admit — mutation-time behavior governs, with no advisory for the unverified case. |

> **Round-trip detection.** The round-trip prover (`analyzeRoundTrip` runs the per-column verdicts + per-authored-column enumeration **once**; `emitRoundTrip` consumes the cache to raise diagnostics) is a **computed deploy-time predicate** over the predicate-honest complement (`viewComplement`), not an enumerated checklist. For the single-source projection-and-filter fragment the complement is *determined, not chosen* (the predicate-honest fan-out resolves the Bancilhon–Spyratos ambiguity), so the two laws are decidable with no theorem prover: **GetPut** holds iff `put` leaves the complement **fixed** (no writable column's write-back targets a complement-hidden base column), and **PutGet** holds iff `get ∘ put` reproduces the written image (the composed forward-of-inverse is the identity on the writable value, and any inverse `domain` is entailed by the residual predicate). The **firing rule** has three branches. (1) A column the lens **presents as writable** (a `base` `UpdateSite`) whose round-trip cannot be proved faithful. (2) A `computed`/opaque output column the author **declared writable** via the per-logical-column tag `quereus.lens.writable = true` ([Computed and Generated Columns](lens.md#computed-and-generated-columns)) — the asserted intent makes an otherwise-admitted read-only column a deploy error. (3) An **authored** (`with inverse`) column — writable by construction (it satisfies the writable intent exactly as an inferred inverse does, so branch 2 never fires for it), with its own law treatment: PutGet by enumeration (`lens.putget-violation` above) and GetPut surrendered into the acknowledgeable `lens.getput-lossy` advisory, suppressed when the enumeration proves the forward bijective. That same proven-bijection verdict — computed once, up front, before key reconstructibility — additionally makes an authored PK **key-reconstructible**: a PK over a proven-bijective inverse deploys *writable* (it classifies `proved` by **bijection transport** onto a declared basis key over the put target — see [Constraint Attachment](lens.md#constraint-attachment)), while the non-injective (lossy) authored PK stays read-only. An opaque column with no intent tag (or `= false`) is an intentional read-only/derived column and emits nothing (its write reds `no-inverse` at mutation time). The intent branch keys off the round-trip *verdict* (which admits an invertible **composed** expression like `(speed + 1) - 2` as writable), not the bare-column reconstructibility test, so a tagged invertible chain does not false-fire. The shipped invertibility registry is faithful by construction (`±k`, identity, passthrough, no-op cast — unrestricted domains), so branch (1) emits nothing today; it is the live seam that reds the day a shape, or a future domain-restricted / composed profile, violates a law. **Degrade-to-safe** (no new error, today's behaviour — the mutation-time and *key reconstructibility* nets still govern): a body that fails to plan, is outside the single-source projection-and-filter fragment (join / aggregate / set-op / `VALUES` / recursive-CTE / `LIMIT`/`OFFSET`/`DISTINCT`), has no threaded `updateLineage`, or carries a non-negation-free residual (`not`/`<>`/`is not` — the signal the complement is not honestly determined). On a degrade-to-safe body **no** branch fires — so an opaque column tagged `quereus.lens.writable = true` whose body is out of fragment does *not* deploy-block (and an authored column on such a body gets neither the enumeration nor the advisory); it still reds at mutation time (this completeness gap is intentional). The body is planned **logically** (preserving the operator tree that threads lineage), so the verdict and the `column_info` writability surface agree by construction. Widening the computed predicate to the join/decomposition fragment tracks with the complement being defined there ([view updateability § Current limitations](view-updateability.md#current-limitations)).

**Warnings — correct but suboptimal:**

| Check | Advisory |
|---|---|
| **No backing index for a set-level constraint** (`lens.no-backing-index`) | A `unique` / primary key with no basis covering structure is enforced by the O(n) commit-time scan. The prover warns and recommends a basis covering index (a materialized view with `order by` over the constraint columns), noting that row-time conflict resolution (`insert or replace` / `or ignore`) *requires* that structure and is otherwise rejected. This advisory **also** covers a logical `unique` over a proven-bijective [authored inverse](lens.md#computed-and-generated-columns) whose put-target basis column is not a declared basis key: the count scan runs over the **logical forward image** (no new enforcement code — the same `synthesizeUniqueCountExpr` path), and an `on conflict replace`/`ignore` on such a commit-time key still reds `lens.unenforceable-conflict-action` (the scan can only ABORT). When the put target *is* a basis key the UNIQUE is `proved` by bijection transport and emits **no** advisory. (A child-side FK existence check is *not* covered by this advisory: its equality predicate the optimizer pushes into a basis index seek when one answers it, degrading to an O(n) scan otherwise.) |
| **No answering structure for a declared access pattern** (`lens.no-answering-structure`) | If the logical schema (or its tags) declares an expected lookup/ordering with no basis ordering or index to serve it, the prover warns that reads will scan. |
| **Partial override** (`lens.partial-override`) | When an override covers only some columns of a table and the remainder took the default alignment, the prover emits an informational note listing the gap-filled columns, so the generated portion is visible. |
| **Lossy write-through** (`lens.getput-lossy`) | A column writable through an [authored inverse](lens.md#computed-and-generated-columns) whose forward mapping is not proven injective: GetPut is surrendered — a write-through *normalizes* the base value to the inverse's representative. Intentional for migration-style code-collapsing mappings, so it is advisory and acknowledgeable, never an error; enumeration that proves the mapping bijective (over a CHECK-constrained domain) suppresses it. The bijectivity proof trusts a basis CHECK domain only through the `permitsGrandfatheredCheckViolators` capability gate (`getTrustedCheckExtraction`): a basis table on a module that grandfathers CHECK violators may hold rows outside its declared domain, so its enumeration cannot witness the bijection and the advisory stands. |
| **Grandfathered NOT NULL** (`lens.nullability-mismatch`, demoted form) | Dual-severity twin of the error row above: over a basis whose every module declares `permitsGrandfatheredNotNullViolators`, a `not null` logical column with a nullable basis-derived expression deploys with this advisory instead of blocking, and reads may yield NULL there. **The tolerance is read-side only:** a forward write through the lens still enforces the declared NOT NULL — the obligation classifies `enforced-row-local` and rides the same seams as a row-local CHECK (see *Constraint Attachment*), rejecting as `NOT NULL constraint failed: <table>.<col>` — while stored rows stay readable and are never scanned at deploy. Acknowledgeable and escalatable per table via `error-on: lens.nullability-mismatch`. |
| **Over-restrictive basis key** (`lens.over-restrictive-basis-key`) | A `proved` logical key (PK / `unique`) that is a strict **superkey** of a NOT-NULL basis key — e.g. logical `unique(a, b)` body-proved over basis NOT-NULL `unique(a)` (or basis PK `(a)`). The logical key is intrinsically unique (the warning never downgrades it from `proved`), but the basis enforces uniqueness on a *subset* of its columns, so it rejects two rows differing only outside the basis key's columns that the logical schema advertises as valid. Sound but stricter than declared, so it is advisory and acknowledgeable, never an error; the remedy is to widen the basis key to match or narrow the logical key. Fires only for a **strict** subset (an exact-match basis key is fully realizable and never warns) and only on the single-source `proved` path (a nullable basis sub-key yields a guarded FD and never classifies `proved`; a multi-source body has no 1:1 basis-column mapping — both documented gaps). |

Warnings are reported through the same channel as the compile result (and surfaced in the deploy summary); they never block a deploy. The backing-index warning is the lens layer's single most important advisory, because it is the one place where the "structure is optional, correctness isn't" separation has a visible performance cost the developer should consciously accept or remedy. The recommended remedy is detailed in [Derived-Row Constraints § Covering structures](mv-constraints.md#covering-structures).

## Acknowledging advisories

Advisories only reduce noise if acknowledged ones stay out of the way — but an acknowledgment must never hide a *newly* important problem. The mechanism balances both:

- **Coded and sited.** Every advisory carries a stable code and the logical site it concerns (table / constraint / column), so an acknowledgment targets exactly one advisory, never a class. An optional `:<target>` segment narrows an ack to a specific column/constraint when a table has several instances of one code.
- **Acknowledged in source, via a reserved tag.** A `quereus.lens.ack.<code>[:<target>]` tag on the logical table or constraint suppresses that advisory from the default report. Because the ack lives in the logical declaration, it is version-controlled and shows up in review — there is no hidden, out-of-band suppress-list. The tag value is a **required rationale** (an empty or missing rationale is itself a warning — the ack still suppresses, but its justification is flagged), so every suppression carries its justification.
- **Tallied, never vanished.** The deploy summary always reports `acknowledged: N` and can expand them on demand: `select * from quereus_lens_advisories('x')` yields one row per advisory of the last deploy — `active`, `re-surfaced`, `acknowledged`, or `acknowledged-unconditional` — with its rationale and current/recorded fingerprints. The default view is decluttered; nothing becomes truly invisible.
- **Re-surfaces on material change.** The prover fingerprints the facts behind each advisory (constraint columns, the presence/absence of a covering structure, a **coarse cardinality band**, the backing basis relation — and, for `lens.getput-lossy`, the column's enumerable CHECK domain, so the `in (...)` list gaining a value re-surfaces the ack; and, for `lens.over-restrictive-basis-key`, the governing basis key's columns, so widening or loosening the basis key re-surfaces the ack) as a stable base64url FNV-1a digest. The recorded fingerprint is stored **in the DDL**, as a trailing `#fp=<digest>` token on the ack tag value — so it survives schema export round-trip, is version-controlled, and shows up in review. If the facts later diverge — the table crosses a cardinality band, the constraint columns change, a previously-present covering structure is dropped — the recomputed fingerprint no longer matches and the advisory **re-surfaces as un-acknowledged**, flagged *"previously acknowledged; situation changed."* This is the anti-fatigue guarantee that still catches the thing that matters. A first-write ack with no recorded `#fp=` is honored but marked *unconditional* — the author has explicitly opted out of re-surfacing.
  - **Cardinality bands** (so an ack survives ordinary row-count churn — only a band *crossing* re-surfaces it): `empty` (0 rows), `small` (< 1e3), `medium` (< 1e6), `large` (≥ 1e6), `unknown` (no estimate).
- **Escalation policy.** A per-logical-table policy — the reserved tags `quereus.lens.policy.error-on` / `quereus.lens.policy.require-ack`, each a CSV of advisory codes — promotes specific codes beyond advisory. It is **default-empty**: out of the box no code is escalated; a project opts in by tagging each table.
  - `error-on: [code]` — the code is always a hard error; an ack cannot suppress it. For invariants you never permit.
  - `require-ack: [code]` — an un-acknowledged instance is an error, but a valid (fingerprint-matched or first-sight) ack with rationale clears it. This is the sweet spot for `lens.no-backing-index`: it forces a conscious, documented decision without blocking the developer who has genuinely accepted the commit-time scan.
  - **Unknown codes fail loud, never open.** A policy entry naming no real advisory code (a typo or stale code) is a hard deploy error — a governance control that fails open is the worst failure mode. The recognized targets are exactly the warning-severity advisories that flow through governance (`lens.no-backing-index`, `lens.no-answering-structure`, `lens.partial-override`, `lens.pk-not-reconstructible`, `lens.getput-lossy`, `lens.over-restrictive-basis-key`), validated against the prover's single exported vocabulary so the list cannot drift from what the prover emits. (The error-severity codes are already hard errors and are not governable.)

```sql
declare logical schema X {
  table Car (
    id int primary key,
    vin text,
    unique (vin)
  ) with tags (
    -- rationale + recorded fingerprint (the `#fp=` token is appended once the
    -- advisory's facts are known; a bare rationale is honored unconditionally):
    "quereus.lens.ack.no-backing-index:vin" = 'low-write table; commit-time scan is acceptable #fp=Ab3k_92xQ1pe',
    -- opt this table into forcing a conscious decision on the same code:
    "quereus.lens.policy.require-ack" = 'lens.no-backing-index'
  );
}
```

Acknowledgment suppresses the *warning* only; it has no effect on an `error-on` escalation or on any correctness error from the [coverage checklist](#coverage-checklist).

The reserved `quereus.lens.*` tag shape and site are validated by a typed registry that is the **single source of truth for the entire `quereus.*` namespace** — the view-mutation override surface, the module advertisement builder, and the physical declarative-schema differ all validate through it with one unified hard-error-on-unknown severity. Each key is matched to a frozen spec that checks its site and validates its value; `quereus.lens.ack.<code>` carries a required-nonempty-rationale whose empty/missing case is a warning, while an unknown or mis-sited `quereus.lens.*` key is a hard error. The lens-specific keys and their sites: `quereus.lens.ack.<code>` (logical table / constraint), `quereus.lens.access.<col>` and `quereus.lens.policy.{error-on,require-ack}` (logical table), `quereus.lens.writable` (boolean, **logical column** — the [writable-intent signal](lens.md#computed-and-generated-columns)), and the `quereus.lens.decomp.*` family (basis tables). A reserved key on a logical column — including a typo or a mis-sited key — is now validated at the `logical-column` site, so it fails loud the same way the table / constraint sites do.
