# Pre-existing failure: `yarn lint` fails on the type-check pass over `bench/lib/`

Surfaced while working `2.21-bench-counter-suite-passes` (implement).

## Command

From the repo root:

```
yarn workspace @quereus/quereus run lint
```

That script is `eslint 'src/**/*.ts' 'test/**/*.ts' && tsc -p tsconfig.test.json --noEmit`.
The eslint half passes; the `tsc` half exits 1.

## Failing output (verbatim, complete)

```
bench/lib/compare.mjs(80,21): error TS7006: Parameter 'status' implicitly has an 'any' type.
bench/lib/compare.mjs(95,19): error TS7006: Parameter 'prefix' implicitly has an 'any' type.
bench/lib/compare.mjs(95,27): error TS7006: Parameter 'part' implicitly has an 'any' type.
bench/lib/compare.mjs(120,15): error TS2322: Type 'unknown' is not assignable to type 'string | number | boolean | null'.
bench/lib/compare.mjs(307,57): error TS2559: Type 'BenchmarkSummary' has no properties in common with type '{ counters?: unknown; }'.
bench/lib/counters.mjs(23,31): error TS7006: Parameter 'db' implicitly has an 'any' type.
bench/lib/counters.mjs(44,37): error TS2345: Argument of type 'unknown' is not assignable to parameter of type 'SqlParameters | SqlValue[] | undefined'.
```

All seven are in `packages/quereus/bench/lib/`.

## Why it is pre-existing

`packages/quereus/tsconfig.test.json` sets `"include": ["test/**/*", "src/**/*", "bench/lib/**/*"]`.
My ticket modified only `packages/quereus/bench/suites/*.bench.mjs` — four files, confirmed by
`git status --porcelain` — and `bench/suites/` is not in that include list, nor is it reachable
by a static import from anything that is (`bench/lib/discover.mjs` loads suites through a
computed dynamic `import()`, which TypeScript does not follow). The seven diagnostics are also
each local to their own file: missing JSDoc `@param` annotations on `noCounters`, `joinPath`
and `enableMetrics`, and three `unknown`-typed values used where a narrower type is required.
Nothing in my diff can reach any of them.

The two files were added by commit `9e6bbcd2f` (`ticket(implement): bench-counter-reporting`),
the immediately preceding ticket, which is where the errors were introduced.

## Root-cause sketch (for whoever picks this up)

Each one is an annotation gap rather than a logic defect — but they should be fixed by typing
the values correctly, not by widening to `any` or by dropping `bench/lib/**/*` back out of the
type-check include, which is what makes the pass worth having in the first place:

- `compare.mjs:80` `noCounters` — annotate the `status` parameter as `CounterStatus`.
- `compare.mjs:95` `joinPath` — annotate `prefix` and `part` as `string`.
- `compare.mjs:120` — `flattenCounters` assigns a value narrowed only to "not an object" into a
  `Record<string, number|string|boolean|null>`; it needs a narrowing check or a cast that states
  why the remaining primitive types are the only ones reachable.
- `compare.mjs:307` — `compareCountersOne` is declared to take `{counters?: unknown}` and is
  handed a `BenchmarkSummary`; the typedef should reference the real summary type.
- `counters.mjs:23` `enableMetrics` — has no JSDoc at all; needs the `Database` `@param` its
  siblings in the file already carry.
- `counters.mjs:44` — `snapshotStatement`'s `params` is `@param {unknown}` but is forwarded to
  `stmt.all()`, which wants `SqlParameters | SqlValue[] | undefined`. The JSDoc type is simply
  wrong and should name the parameter type the call site requires.
