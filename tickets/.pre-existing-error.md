## Pre-existing failure surfaced while implementing `perf-store-row-deserialize-reviver-fast-path`

**Command run** (from repo root):

```
yarn workspace @quereus/store run test
```

**Failing tests** — all in `packages/quereus-store/test/serialization.spec.ts` (added by this
ticket to cover the edge-case list the ticket itself specifies):

1. `Row Serialization > reviver fast-path gate (property) > deserializeRow(serializeRow(row)) round-trips for many generated shapes`
2. `Row Serialization > reviver fast-path gate (property) > deserializeValue(serializeValue(value)) round-trips for many generated shapes`
3. `Row Serialization > reviver fast-path gate (edge cases) > round-trips a JSON column with a real $bigint key, unwrapped form`
4. `Row Serialization > reviver fast-path gate (edge cases) > round-trips a JSON column with a real $bigint key inside a $json wrapper on read-back`
5. `Row Serialization > reviver fast-path gate (edge cases) > round-trips a marker nested inside an array inside an object`

**Error excerpt** (representative — #1, #3, #4, #5 all throw the same way; #2 silently
mis-converts instead of throwing):

```
1) Row Serialization
     reviver fast-path gate (edge cases)
       round-trips a JSON column with a real $bigint key, unwrapped form:
   SyntaxError: Cannot convert not-a-bigint to a BigInt
    at BigInt (<anonymous>)
    at Object.reviver (packages/quereus-store/src/common/serialization.ts:104:20)
    at JSON.parse (<anonymous>)
    at deserializeRow (packages/quereus-store/src/common/serialization.ts:50:17)

2) ... deserializeValue(serializeValue(value)) round-trips ...
   AssertionError: expected [ 7, 'x', Uint8Array[ 125, 169, 30 ] ] to deeply equal [ 7, 'x', { '$blob': 'fake' } ]
```

**Why this is pre-existing, not caused by this ticket:** this ticket only changes *when*
`reviver` is invoked (added a marker-sigil gate so `JSON.parse` skips the reviver callback
for rows that provably can't contain a marker) — it does not touch the `reviver` function's
body at all. Every failing case above contains the literal `{"$` sigil, so the gate
evaluates true and `reviver` is invoked exactly as it always was pre-ticket. Reproduced the
identical throw against the unmodified `reviver`/`wrapJsonIfNeeded` pair directly (bypassing
the gate) to confirm.

**Root cause** (single site, `packages/quereus-store/src/common/serialization.ts`,
`reviver` + `wrapJsonIfNeeded`): `wrapJsonIfNeeded` only wraps a value in `{"$json": ...}`
when the *value itself* is a plain object with a top-level `$bigint`/`$blob` key — it never
wraps arrays, and it never looks inside nested objects. Separately, `JSON.parse`'s reviver
walk is bottom-up: for `{"$json": {"$bigint": "not-a-bigint"}}`, the reviver visits the
inner `{"$bigint": "not-a-bigint"}` object *before* it ever sees the outer `"$json"` key, so
the inner object is misidentified as a real bigint marker and `BigInt("not-a-bigint")`
throws — the wrap never gets a chance to protect it. The same ordering issue lets a
`$blob`-shaped object nested inside an array silently decode as base64 into a wrong
`Uint8Array` instead of throwing (case 2). Net effect: any JSON/object or array `SqlValue`
whose content happens to contain a key literally named `$bigint`, `$blob`, or `$json` in a
single-key-object shape is either mis-converted or crashes on read-back, regardless of
nesting depth — the wrap/unwrap mechanism does not actually achieve the collision-proofing
its own module doc comment claims.
