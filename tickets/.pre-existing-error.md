# Pre-existing failure: `yarn docs:check` — `docs/types.md` is past the 12,000-word cap

## Command

```
yarn docs:check          # from repo root; runs scripts/check-docs.mjs
```

## Failure

```
docs/types.md: 12852 words exceeds the 12000-word cap for an unratcheted doc — split it,
or record it with --update-ratchet --force and say why in the commit message

1 documentation failure(s). See docs/doc-conventions.md.
```

`docs/types.md` has no entry in `docs/.doc-budget.json`'s `ratchet` map, so the checker
holds it to the flat 12,000-word cap with no grace band.

## Why it is pre-existing

At `HEAD` (commit `6fee62bf`, before any edit in this ticket) the file already measured
**12,498 words** — 498 over the cap — so `yarn docs:check` failed identically before this
ticket touched anything:

```
git show HEAD:docs/types.md | wc -w   # → 12498
```

(The checker counts words as `content.split(/\s+/).filter(Boolean).length`, i.e. the same
count `wc -w` reports.)

## Disclosure — this ticket did add words to the failing doc

Ticket `3-binary-op-result-types-match-runtime` added a `## Binary operator result types`
section to `docs/types.md` (that is the correct home for it, and the ticket's TODO
required the doc update). The file went from 12,498 → 12,852 words, so **+354 of the
current overage is from this ticket**; the doc was already over the cap without it.

Splitting `types.md` into a topic doc (the pattern `docs/types-ordering.md` already
follows) is out of scope here — it is a whole-document reorganization, not a
binary-operator change. Three other docs are also flagged as near-cap in the same run
(`design-isolation-layer.md` 127 away, `optimizer.md` 23 away, `sql-ddl.md` 250 away), so
the split is worth planning as one piece of work rather than four.

No test suite fails: `yarn test`, `yarn test:store`, `yarn lint` and `yarn typecheck` are
all green.
