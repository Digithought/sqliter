## Why it is pre-existing (and not mine)

- The diff under review touches only `packages/quereus/src/planner/building/select-aggregates.ts`
  and two `packages/quereus/test/logic/*.sqllogic` files. It is a build-time SQL planner
  change with no sync, replication, or storage surface at all.
- `yarn workspace @quereus/quereus test` passes on its own: **10173 passing, 25 pending,
  0 failing**.
- Re-running the failing package alone reproduces nothing: `yarn workspace @quereus/sync test`
  → **736 passing, 0 failing** in 40s.

## Likely root cause, for whoever triages this

`packages/quereus-sync`'s test script invokes Mocha with no `--timeout`, so it runs at
Mocha's 2000ms default:

```
packages/quereus-sync/package.json:46
"test": "cd ../.. && node --import ./packages/quereus-sync/register.mjs node_modules/mocha/bin/mocha.js \"packages/quereus-sync/test/**/*.spec.ts\" --reporter min --colors",
```

`packages/quereus` already hit this and fixed it — `packages/quereus/test-runner.mjs`
defaults to `--timeout 10000` with a comment naming the exact cause ("can be starved past
Mocha's 2s default when the machine is under concurrent load (e.g. a background ticket
runner)"). The sync suite does real async work in its hooks and has the same exposure with
none of that headroom. Several other workspaces invoke Mocha the same bare way and are
presumably exposed identically.

This is a flake, not a broken assertion — but it is a flake with a known, cheap cause, and
it will keep costing whole `yarn test` runs until the timeout is raised (or the hook is made
to not need >2s).

No test was skipped, disabled, or loosened.
