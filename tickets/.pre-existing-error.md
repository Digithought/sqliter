# Pre-existing test failure

## Command

```
yarn build          # required — the failure is masked by a stale packages/quereus/dist
yarn test
```

Failing workspace: `@quereus/isolation` (`packages/quereus-isolation`).
Reproduces alone with `yarn workspace @quereus/isolation test`.

## Failing test

`packages/quereus-isolation/test/alter-table-conformance.spec.ts:386`

```
ALTER over staged overlay rows (isolation layer)
  honored ADD COLUMN migrates a staged overlay row forward (NULL in the new column)

QuereusError: NOT NULL constraint failed for column 'score' added to main.t
  — column has no DEFAULT and existing rows cannot be backfilled
    at validateNotNullBackfill (packages/quereus/src/runtime/emit/alter-table.ts:847)
    at runAddColumn (packages/quereus/src/runtime/emit/alter-table.ts:492)
    at Context.<anonymous> (packages/quereus-isolation/test/alter-table-conformance.spec.ts:390)
```

The test opens a transaction, stages `insert into t values (1, 'Alice')`, then runs
`alter table t add column score integer` and expects it to be honored with `score = null`.

## Why it is pre-existing

`bug-add-column-default-null-notnull-hole` (commits 48fcbad3 / 06c98860, both already on
`main`, both before this ticket's work) changed `runAddColumn` to resolve the new column's
mandatoriness through `columnDefToSchema` + the session `default_column_nullability`
option, which ships as `not_null`. `score integer` with no `null` marker and no DEFAULT is
therefore a mandatory column, and the table is non-empty (in the issuer's own merged view),
so the engine now rejects the statement. The test still asserts the pre-change behaviour —
that the column is added and the staged row carries NULL in it.

The failure is at HEAD with a clean tree: I reverted my only source edit (a throwaway probe
in `packages/quereus-isolation/src/alter-migration.ts`) and re-ran, and it still fails. My
ticket (`bug-add-column-notnull-skips-other-connections-uncommitted-rows`) produced no source
changes at all — its output is an implement ticket.

Note: it is invisible unless `yarn build` is run first. `packages/quereus-isolation` tests
import `@quereus/quereus` from its built `dist`, so a stale `dist` still contains the
pre-change `runAddColumn` and the suite passes. That is almost certainly why the sibling
ticket's runs went green.

The fix is a test update, not an engine change: the "honored" arm needs a column that is
actually optional under the shipped default (`add column score integer null`) or one with a
usable DEFAULT (`add column score integer default 0`). Both spellings are already covered
elsewhere in the same file's matrix, so pick whichever keeps the arm's intent — proving a
staged overlay row is migrated forward, carrying the new column's backfilled value.
