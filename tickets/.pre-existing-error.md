# Pre-existing failure: `yarn docs:check` — two docs already over the word cap

## Command

```
yarn docs:check          # from the repo root (scripts/check-docs.mjs)
```

## Failure

```
docs/runtime.md: 12185 words exceeds the 12000-word cap for an unratcheted doc — split it,
  or record it with --update-ratchet --force and say why in the commit message
docs/types.md: 13461 words exceeds the 12000-word cap for an unratcheted doc — split it,
  or record it with --update-ratchet --force and say why in the commit message

2 documentation failure(s). See docs/doc-conventions.md.
```

`yarn docs:check` is the first step of the root `yarn check` chain, so this fails `check`.

## Why it is pre-existing

Both docs were already past the cap at HEAD (`d3fa3c8a`), before this ticket's edits.
`scripts/check-docs.mjs` counts words as `content.split(/\s+/).filter(Boolean).length`,
i.e. exactly `wc -w`, and neither doc has a `docs/.doc-budget.json` ratchet entry (the only
entry is `docs/lens.md`):

```
$ git show HEAD:docs/types.md   | wc -w   → 12896   (cap 12000)
$ git show HEAD:docs/runtime.md | wc -w   → 12007   (cap 12000)
```

## What this ticket contributed

The `representation-strict-checker` ticket required documenting the new
`QUEREUS_REPR_STRICT` harness, which added roughly 560 words to `docs/types.md`
(§ Enforcement) and 180 to `docs/runtime.md` (§ Strict physical-representation test mode).
That growth is on top of an already-failing check, not the cause of it — removing the new
sections would leave both docs over the cap.

## Not resolved here, deliberately

The sanctioned remedies are to **split** each doc or to re-baseline with
`--update-ratchet --force`. Both are editorial decisions about docs this ticket does not
own: splitting `types.md` / `runtime.md` is a structural change across many inbound links,
and force-ratcheting would silently grandfather the pre-existing overflow that the cap
exists to surface. Neither should be decided inside an implementation ticket.
