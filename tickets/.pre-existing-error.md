# Pre-existing failure: `yarn docs:check` is red on two over-cap docs

## Command

From the repo root:

```
node scripts/check-docs.mjs      # == `yarn docs:check`, the FIRST step of `yarn check`
```

## Failures

```
docs/module-authoring.md: 12001 words exceeds the 12000-word cap for an unratcheted doc — split it, or record it with --update-ratchet --force and say why in the commit message
docs/store.md: 12334 words exceeds the 12000-word cap for an unratcheted doc — split it, or record it with --update-ratchet --force and say why in the commit message

2 documentation failure(s). See docs/doc-conventions.md.
```

Four other docs are reported as warnings only (near the cap, or inside `docs/lens.md`'s
grace band) and do not fail the run.

## Why this is pre-existing

Both were already over the cap at `82b375fd` (the commit under review), before any edit in
this ticket:

```
git show HEAD:docs/module-authoring.md | wc -w   # 12001
git show HEAD:docs/store.md            | wc -w   # 12332
```

`docs/module-authoring.md` is untouched by this ticket entirely. `docs/store.md` was
edited here only to re-measure a stale source-line-count NOTE (net +2 words against a
doc already 332 words over the cap); it fails for the same reason at HEAD.

The rest of the gate is green with this ticket's changes applied: `yarn lint`,
`yarn typecheck`, `yarn test` (full workspace), and `yarn test:store` (9307 passing) all
pass.

## Fix shape

Neither doc is a test, so nothing was skipped or loosened. The resolution is either a
split (`docs/doc-conventions.md` describes the convention) or an explicit
`--update-ratchet --force` recording with the reason in the commit message — a call that
wants a human, since it decides whether these two docs are allowed to stay big.
