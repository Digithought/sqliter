# An alias on a FROM source hides every unqualified column reference under it

`ALTER TABLE … RENAME COLUMN` and `ALTER TABLE … DROP COLUMN` both decide "does
this stored expression reference this column?" with one scope-aware walk. That
walk treats a FROM source carrying an alias (`from t as a`) as contributing **no
columns to unqualified name resolution**. SQL says the opposite: an alias adds a
qualifier, it does not remove the source's columns from scope, so a bare `x`
written against `from t a` binds `t.x` exactly as it would against `from t`.

Everything downstream inherits the blind spot. The alias-*qualified* spelling
(`a.x`) is handled correctly throughout — only the unqualified one is lost.

## Verified behaviour

Run against the engine as it stands. Each block is the whole reproduction.

**A rule is silently orphaned, and the whole database stops accepting writes.**

```sql
create table t (id integer primary key, x integer);
create table other (id integer primary key);
create assertion a1 check (not exists (select 1 from t a where x < 0));

alter table t drop column x;      -- accepted; should be refused
insert into other values (1);     -- ERROR: Column not found: x
```

Assertions are recompiled on any commit that touched any table, so the broken
one blocks writes to tables it has nothing to do with. Writing `from t` instead
of `from t a` refuses the drop correctly.

**A CHECK on another table is orphaned the same way**, leaving that table
unwritable:

```sql
create table t (id integer primary key, x integer);
create table u (id integer primary key, n integer,
                constraint ck check (n < (select max(x) from t a)));

alter table t drop column x;      -- accepted; should be refused
insert into u values (1, 5);      -- ERROR: Column not found: x
```

**A view republishing through a star over an aliased source is not recognised as
a republisher**, so neither verb follows it:

```sql
create table t (id integer primary key, x integer);
create view v as select * from t a;
create assertion a1 check (not exists (select 1 from v where x < 0));

alter table t drop column x;      -- accepted; should be refused
```

```sql
create table t (id integer primary key, x integer);
create view v as select * from t a;
create view w as select x from v;

alter table t rename column x to z;
select * from w;                  -- ERROR: Column not found: x
```

**`RENAME COLUMN` leaves bodies broken** wherever the reference sits under an
alias — a view body and an assertion body shown here:

```sql
create table t (id integer primary key, x integer);
create view v as select x from t a;
alter table t rename column x to z;
select * from v;                  -- ERROR: Column not found: x
```

```sql
create table t (id integer primary key, x integer);
create assertion a1 check (not exists (select 1 from t a where x < 0));
alter table t rename column x to z;
insert into t values (1, 1);      -- ERROR: Column not found: x
```

## Root cause — one site

`packages/quereus/src/schema/rename/column-rename.ts`. The walk's per-frame
state (`ScopeFrame`) carries three overlapping views of a FROM clause:

- `unaliased` — sources with no alias, keyed by bare name.
- `aliasMap` — sources with an alias, keyed by the alias.
- `realSources` — every real-table source, **aliased or not**.

`unaliased` is then used as if it meant "the sources an unqualified column name
can bind to", which is what `realSources` actually holds. Four consumers read it
that way:

- `isTableInUnaliasedScope` — decides whether a bare column reference is captured
  by the walk at all. This is the arm behind every reproduction above.
- `frameBindsTargetUnaliased` — the shared predicate the other three call.
- `isResultColumnExposure`, star arm — decides whether a bare `*` republishes the
  column, so a `select * from t a` view never becomes a rename-cascade target or
  a DROP-guard republication target.
- `isResultColumnExposure`, bare-column arm — same question for `select x from t a`.

The file already contains the *correct* spelling of the star question twice, which
is the sharpest evidence that the representation, not any one call, is the bug:
`starCoversRenamed` inside the select case ORs `aliasMap`'s values in, and
`resultColumnPublishesName` (backing `bodyPublishesColumnNamed`) sweeps
`realSources`. Three spellings of one question, two right and one wrong.

## What to aim for

Make the bad state unrepresentable rather than fixing four call sites: the frame
should expose **one** named accessor for "sources whose columns an unqualified
name in this frame can bind to", and `unaliased` should be reduced to what its
name says — the map of bare names usable as *qualifiers* — with no consumer
reading it for column binding. Every existing consumer then either asks the new
accessor or asks `unaliased` for a qualifier, and there is no third option to
get wrong next time.

Care is needed on two interactions the walk already handles through `unaliased`,
and which the new accessor must keep:

- An **exposing CTE** bound unaliased registers itself in `unaliased` (not in
  `realSources`), and an aliased exposing CTE registers in `aliasMap`. Both must
  keep binding unqualified refs.
- `isTableInUnaliasedScope` consults `resolveColumnInSource` over `realSources`
  to stop an outer seed from capturing a name an inner frame legitimately binds.
  Widening the binding set widens that shadow check in the same step, which is
  the intent — but it is the part most likely to move existing expectations.

## The test that should outlive the fix

A generalized test over **body spellings**, not a case per reproduction above.
One table `t(id, x)`, one list of ways a body can read or republish `x`
— `select x`, `select x from t a`, `select *`, `select t.*`, `select a.*`,
`select * from t a`, the same under a join, under a CTE, under an alias that
shadows, and the currently-unsupported aliased-subquery and function sources —
driven through both verbs, asserting for each:

- `RENAME COLUMN` leaves every dependent body **planable** afterwards (query it,
  do not just compare text), and
- `DROP COLUMN` **refuses** whenever a live rule reads the column through that
  spelling, and **accepts** whenever no rule does.

That single generator covers the whole class, pins rename/drop parity as a
property rather than as paired hand-written cases, and would have caught each
instance here.

## Known related residual (same table, different difficulty)

A star over an **aliased subquery source**, a function source, or a CTE
(`create view v as select * from (select * from t) s`) has no askable column set
today, so a republication arriving only that way is invisible to both verbs —
verified, same symptom. It is documented on `bodyPublishesColumnNamed` and on
`ScopeFrame.realSources`. Unlike the alias case it needs recursive column-set
inference on the inner body rather than a representation fix, so treat it as a
second arm to scope separately, not as part of the first fix.
