# Why

`bench-gate-reference` (landed) gates on exact work counters. This ticket adds the second
portable measurement — a bound on one benchmark's median against another's *in the same
run* (a "ratio guard") — to `yarn bench:gate`. A within-run ratio cancels machine speed,
which is what makes it gateable when an absolute millisecond figure is not. Today the one
guard (`execution/correlated-subquery` vs `hand-batched-peer-count`, max 10x) only runs
under manual `yarn bench`.

A sibling ticket `bench-gate-check-wiring` (prereq: this one) wires the gate into
`yarn check`, adds new guards, and updates docs. This ticket is the guard engine only.

# Investigation findings (verified against current code — trust these, skip the re-read)

- `checkRatioGuards` / `reportRatioGuards` live at `bench/run.mjs:530-627`. Signature:
  `checkRatioGuards(suites, allBenchmarks, selectedNames, filterActive, skippedNames = new Map(), informational = new Set())`.
  Verdict record: `{ target, baseline, ratio: number|null, maxRatio, status, detail }`.
  Status decision order (load-bearing, keep exactly): (1) either member `informational` →
  `misconfigured` — checked FIRST; (2) either member in `skippedNames` → `not-evaluated`;
  (3) either member not in `selectedNames` → `skipped` if filter active, else
  `misconfigured`; (4) member missing from `allBenchmarks` (ran but failed) →
  `not-evaluated`; (5) ratio computed with degenerate-median rule: baseline median 0 →
  target>0 ? Infinity : 1; ratio > maxRatio → `failed`, else `ok`.
- `reportRatioGuards` prints via `run.mjs`'s module-local `say`/`red`/`yellow` closures and
  returns the count of `failed` + `misconfigured`. Moving it to `lib/guards.mjs` means the
  printer must take injected output helpers (e.g. `(verdicts, {say, red, yellow})`) or
  return formatted lines — run.mjs and gate.mjs each have their own `say`/color set.
- **run.mjs and gate.mjs both execute `main()` at import** — neither can import from the
  other. That is why guards.mjs must be a pure `bench/lib/` module (also puts it in the
  type pass: `tsconfig.test.json` includes `bench/lib/**`, not `bench/*.mjs`).
- run.mjs call site is lines ~961-977: builds `selectedNames` (Set of fullNames from
  `selectBenchmarks`), `skippedNames` (Map name→reason), `informational` from
  `informationalNames(suites)` (discover.mjs), passes `allBenchmarks` keyed by fullName
  where each value is a `summarize(...)` record carrying `median_ms`.
- Guard names resolve today as `${suite.name}/${guard.name}` inside the declaring suite
  only. Cross-suite: a name containing `/` should be used as-is; bare names keep resolving
  within the declaring suite. Once resolved to full names, all the existing status cases
  work unchanged (`selectedNames`/`allBenchmarks`/`informational` are all keyed by full
  name across every suite already). A cross-suite name pointing at a nonexistent benchmark
  falls into the existing "not found in this run" → `misconfigured` path with no filter.
- `loadSuite` (bench/lib/discover.mjs:85-131) already validates benchmark shape (`name`,
  `fn`, `counters`, `skip`, `informational`, duplicate names) and returns
  `{ file, name, benchmarks, ratioGuards: mod.ratioGuards ?? [] }`. Add matching loud
  validation for each `ratioGuards` entry: non-empty string `name` and `baseline`, and a
  finite `maxRatio > 0`. Optional `note` field (string) — one sentence on what the guard
  protects, printed with the verdict. The `RatioGuard` typedef is at discover.mjs:55-59.
- Timing in the gate MUST fork (single-process timing moves benchmarks 0.37x-1.66x by
  position). gate.mjs cannot reuse run.mjs's `forkBenchmark` (main-at-import). Either lift
  a minimal fork helper into `bench/lib/` or write a small one in gate.mjs mirroring
  run.mjs:212-274 (fork `bench/child.mjs` with `[suiteFile, benchName]`, classify
  result/failure/skipped/timeout, 120 s timeout). Child sends
  `{type:'result', timings, warmup, batch, pinned}` over IPC; compute the median with
  `summarize` from `bench/lib/stats.mjs`.
- `calibrate(fn, config)` and `collectSamples(fn, plan, config)` in
  `bench/lib/calibrate.mjs` already take a config parameter; `CALIBRATION` is the exported
  default (warmupTargetMs 250, targetTotalMs 1000, maxTotalMs 5000, minSamples =
  MIN_STABILITY_SAMPLES, maxSamples 500). Add `GATE_CALIBRATION` next to it (shorter
  warmup + time target — the existing guard has ~10x headroom, so a looser median is fine).
  child.mjs currently calls `calibrate(fn)` bare (child.mjs:162) and
  `collectSamples(fn, plan)` (child.mjs:165); it already parses trailing flags
  (`flags.includes('--no-counters')`, child.mjs:48-51) — add e.g. `--gate-calibration` to
  select the reduced profile, and pass `--no-counters` from the gate's guard pass (the
  counters pass already covered counters; the guard pass wants timings only).
- gate.mjs deletes `QUEREUS_BENCH_LEVELDB` from its env before `loadSuites()`
  (gate.mjs:410-411) — the guard pass inherits that; keep it.
- gate.mjs structure: `parseArgs` with `VALUE_FLAGS`/`BOOLEAN_FLAGS` sets (gate.mjs:80-110),
  `UsageError` printed as one line, `--json` routes human output to stderr and writes one
  outcome object to stdout last, exit via `process.exitCode` + `finishCleanly`. Add the
  guard verdicts to the JSON output object.

# Architecture (from the plan — decisions already made)

- **Move `checkRatioGuards`/`reportRatioGuards` verbatim into `bench/lib/guards.mjs`**;
  import from both run.mjs and gate.mjs. Preserve every status rule listed above.
- **Guard pass in gate.mjs, after the counters pass**: the timed set is exactly the
  benchmarks named by some guard (guard membership is independent of `counters()`
  declaration). Fork each one at a time via child.mjs under `GATE_CALIBRATION`.
- **Re-measure rule**: a guard that fails under reduced calibration is re-forked once at
  full `CALIBRATION` before it may fail the run. The report shows both measurements as ONE
  verdict (never two rows) and says which decided. This is what stops false failures from
  getting the gate disabled.
- **`--report-only`** (and `QUEREUS_BENCH_GATE_REPORT_ONLY=1` for when the flag cannot be
  threaded): runs the full gate — counters AND guards — prints everything including
  failures, exits 0, and prints a loud banner (same visual treatment as run.mjs's
  environment-mismatch box, run.mjs:671-676) saying the gate did not fail the run. It must
  still exit non-zero on a harness error (bad flag, unreadable reference, suite that will
  not load): it suppresses findings, not breakage.
- **`--filter` in gate mode** narrows both passes consistently; a guard whose members were
  filtered out reports `skipped` (existing rule, survives the move).
- **Prohibitions stay**: no guard may name an `informational` row (misconfigured, checked
  first); no cross-backend guard (`x@backend` vs bare `x`) — documented, not enforced in
  code today; keep it that way.

# Tests (extend test/bench-gate.spec.ts or add test/bench-guards.spec.ts — run no benchmark)

- Every existing `checkRatioGuards` status survives the move: ok, failed, skipped under a
  filter, misconfigured without one, not-evaluated for a failed member, not-evaluated for
  a declined (skipped) member, misconfigured for an informational member checked ahead of
  all others.
- Bare guard name resolves within its own suite; `suite/name` resolves across suites;
  cross-suite name at a nonexistent benchmark is misconfigured.
- `loadSuite` throws on a ratioGuards entry missing `name`, missing `baseline`, or with
  `maxRatio` absent/zero/negative/non-finite.
- Re-measure rule: fail-then-pass does not fail the run; the verdict record carries both
  measurements. (Make the decision logic a pure function in guards.mjs so this needs no
  fork.)
- `--report-only` turns a failing verdict set into exit 0 with findings still printed, and
  does NOT suppress a usage error. (Testable if the exit decision is a pure function.)

Run `yarn workspace @quereus/quereus test` and `yarn workspace @quereus/quereus lint`
(lint type-checks test files) when done.
