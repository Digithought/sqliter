# Why (unchanged from original ticket)

`bench-gate-reference` (landed) gates on exact work counters. This ticket adds the second
portable measurement — a bound on one benchmark's median against another's *in the same
run* (a "ratio guard") — to `yarn bench:gate`. A within-run ratio cancels machine speed,
which is what makes it gateable when an absolute millisecond figure is not. A sibling
ticket `bench-gate-check-wiring` (prereq: this one) wires the gate into `yarn check`,
adds new guards, and updates docs. This ticket is the guard engine only.

# Already done (verify, don't redo)

- **`bench/lib/guards.mjs` (NEW, complete).** Pure module, fully JSDoc-typed (it is in
  the `tsconfig.test.json` type pass via `bench/lib/**`). Exports:
  - `resolveGuardName(suiteName, name)` — bare name → `suite/name` within declaring
    suite; a name containing `/` used as-is (cross-suite).
  - `guardMemberNames(suites, informational)` — full names a guard pass must time;
    excludes members of guards poisoned by an informational member (those guards are
    misconfigured regardless); a member shared with a healthy guard is still collected.
  - `checkRatioGuards(suites, allBenchmarks, selectedNames, filterActive, skippedNames,
    informational)` — moved verbatim from run.mjs, plus name resolution and an optional
    `note` carried from the guard into the verdict. Status decision order preserved
    exactly: informational→misconfigured FIRST; skipped member→not-evaluated; unselected→
    skipped (filter) / misconfigured (no filter); ran-but-failed member→not-evaluated;
    degenerate medians (baseline 0 → target>0 ? Infinity : 1); ratio>maxRatio→failed
    else ok.
  - `decideRemeasuredGuard(reduced, remeasured)` — merges a reduced-calibration FAILED
    verdict with its full-calibration re-evaluation into ONE record: final status/ratio
    from the re-measure, `remeasured: true`, `reducedRatio` kept, detail says which
    decided.
  - `mergeRemeasuredVerdicts(initial, remeasured)` — index-aligned merge (only
    `status: 'failed'` entries replaced); throws on length mismatch. Alignment works
    because `checkRatioGuards` is deterministic over the same suite list — call it
    twice (second time with full-calibration medians overwritten into allBenchmarks)
    and zip.
  - `gateExitCode(failed, reportOnly)` — the pure exit decision: `failed && !reportOnly
    ? 1 : 0`. Harness errors (UsageError) throw before this is consulted.
  - `reportRatioGuards(verdicts, { say, red, yellow })` — printer with injected output
    helpers (run.mjs and gate.mjs each own their stream/colour policy); returns
    failed+misconfigured count. Appends ` [note]` when a verdict carries one.
- **`bench/run.mjs`** — local `checkRatioGuards`/`reportRatioGuards` deleted; imports
  from `./lib/guards.mjs`; call site now `reportRatioGuards(ratioGuards, { say, red,
  yellow })`. `checkRatioGuards` call unchanged (same signature).
- **`bench/lib/discover.mjs`** — `validateRatioGuards(file, ratioGuards)` exported and
  called from `loadSuite`; throws on missing/empty `name` or `baseline`, non-finite or

- **`bench/lib/calibrate.mjs`** — `GATE_CALIBRATION` exported: spread of `CALIBRATION`

# Remaining work

## gate.mjs — guard pass (the main remaining piece)

Architecture decisions already made (follow these; rationale in the original ticket):

- **Fork helper written IN gate.mjs** (it cannot import run.mjs — both run `main()` at
  import). Mirror `run.mjs` `forkBenchmark` (fork `bench/child.mjs`, stdio piped and
  forwarded to the human stream / stderr, IPC `result`/`failure`/`skipped` messages,
  120 s timeout with SIGKILL + 5 s reap backstop, settle on `close`). Args:
  `[suiteFile, benchName, '--no-counters', '--gate-calibration']` for the reduced pass;
  drop `--gate-calibration` for the full-calibration re-measure. Track killed PIDs and
  call `sweepBenchTempDirs(killedPids)` (from `lib/tempdir.mjs`) after the pass; add
  SIGINT/SIGTERM handlers that kill the active child and sweep, like run.mjs.
- **Guard pass runs in gate mode only** (never `--accept`), after the counters pass
  report. Timed set = `guardMemberNames(suites, informational)` ∩ full names of
  `selectBenchmarks(suites, filter)` — i.e. members that exist AND match the filter.
  `selectedNames` passed to `checkRatioGuards` = full names of
  `selectBenchmarks(suites, filter)` (same set run.mjs would run), so the existing
  skipped/misconfigured semantics survive unchanged.
- Summarize child timings with `summarize` from `lib/stats.mjs`
  (`{batch, warmup, pinned}` meta from the result message). Fill `allBenchmarks`
  (fullName→summary) and `skippedNames` (fullName→reason). A member whose fork FAILS:
  record `{fullName, detail}` in a `memberFailures` list, print red, and **delete any
  stale `allBenchmarks` entry** (matters on the re-measure pass — a stale reduced
  median must not be re-evaluated as if it were the full measurement).
- **Re-measure rule**: after `checkRatioGuards`, collect `status === 'failed'` verdicts;
  re-fork the union of their members at full calibration (overwriting entries in
  `allBenchmarks`); run `checkRatioGuards` again over the same suites; fold with
  `mergeRemeasuredVerdicts`. Print a yellow line announcing the re-measure.
- **Exit/failure folding**: `failed = countersFailed || reportRatioGuards(...) > 0 ||
  memberFailures.length > 0`. Member fork failures fail the gate (a guard that cannot
  be evaluated must not read as green) but are findings — suppressed by report-only
  like everything else. Reword the final GATE FAILED block: counters mismatch line
  (with the bench:accept hint) only when countersFailed; add guard-failure and
  member-failure lines when those apply; the green line becomes "...matches the
  reference and every ratio guard holds."
- **`--report-only`** (add to `BOOLEAN_FLAGS`) and env `QUEREUS_BENCH_GATE_REPORT_ONLY`
  (treat any value other than empty/`'0'` as on). `--report-only` with `--accept` is a
  UsageError; the env var is ignored in accept mode. Exit via
  `process.exitCode = gateExitCode(failed, reportOnly)` then `finishCleanly(...)`.
  When reportOnly and failed: print a loud banner (same box treatment as run.mjs's
  ENVIRONMENT MISMATCH box, yellow) saying findings did not fail the run. Also print a
  one-line yellow notice near the top when report-only is active. UsageErrors still
  exit 1 via the existing `main().catch`.
- **Zero-selection check**: current `selectedCount === 0` UsageError must not fire when
  the filter selects no counter-declaring benchmark but DOES select a guard member —
  relax to: error only when both counter-selected and guard-member-selected
  (`matchesFilter` over `guardMemberNames`) are zero (accept mode keeps the old rule).
- **JSON output additions**: `ratio_guards` (verdicts), `guard_member_failures`,
  `report_only`. `failed` stays honest (true even under report-only — only the exit
  code is suppressed).
- Keep the existing `QUEREUS_BENCH_LEVELDB` env deletion before `loadSuites()` — forked
  children inherit the cleaned env, which is what keeps LevelDB rows out of the pass.
- Update USAGE string and the file header comment (guard pass + --report-only).

## test/bench-guards.spec.ts (NEW — runs no benchmark)

Import from `../bench/lib/guards.mjs` and `validateRatioGuards` from
`../bench/lib/discover.mjs` (pattern: `test/bench-gate.spec.ts`). Cover:

- Every `checkRatioGuards` status: ok; failed; skipped under filter; misconfigured
  without one; not-evaluated for a member absent from allBenchmarks (ran-but-failed);
  not-evaluated for a skipped member; misconfigured for an informational member checked
  FIRST (make the member also skipped + unselected to prove precedence). Degenerate
  medians: baseline 0 & target>0 → failed with Infinity; both 0 → ok ratio 1.
- Name resolution: bare resolves in own suite; `suite/name` crosses suites; cross-suite
  name at a nonexistent benchmark → misconfigured (no filter). `note` carried into the
  verdict.
- `validateRatioGuards`: throws on missing name / missing baseline / maxRatio absent,
  zero, negative, non-finite, non-number / non-string note; accepts a valid entry with
  and without note; non-array export throws.
- `decideRemeasuredGuard` / `mergeRemeasuredVerdicts`: fail-then-pass → final ok,
  `remeasured: true`, carries `reducedRatio` and final `ratio`, detail names both;
  fail-then-fail stays failed; non-failed initial verdicts pass through untouched
  (identity); length mismatch throws.
- `gateExitCode`: (true,false)→1, (true,true)→0, (false,*)→0.
- `guardMemberNames`: collects both members, resolves cross-suite, drops members of an
  informational-poisoned guard, keeps a shared member reachable via a healthy guard.
- `reportRatioGuards`: with a collecting `say` and identity colours — returns
  failed+misconfigured count; prints the note.

Fixtures are cheap: `checkRatioGuards` only reads `suite.name`, `suite.ratioGuards`,
and `median_ms` off summaries — `{ median_ms: 5 }` objects suffice.
