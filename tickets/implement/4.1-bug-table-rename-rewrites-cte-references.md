# The table-rename walk has no notion of scope; the column-rename walk does

`visitTableRename` in `rename-rewriter.ts` matches a name **anywhere in the AST**.
Its sibling `visitColumnRename` carries a `ScopeFrame` stack (CTE names in scope,
alias map, row-image rebinding) and consults it before every rewrite. The table
walk consults nothing, so it rewrites two kinds of name that are not references
to the renamed table.

## Over-match 1 — a name bound inside the body

```sql
create table zap (id integer primary key, k integer);
create view v as with zap as (select 1 as k) select k from zap;
alter table zap rename to zap2;
```

The `from zap` inside the view resolves to the **CTE**, not the table. The walk
rewrites it to `from zap2`, so the view now reads the real (renamed) table and
the CTE it declared goes unused — a silent change of meaning. The same defect
covers every other way a name can be bound inside the body: an aliased subquery
source (`from (select 1 as x) zap`), an aliased table source (`from other zap`),
and a function source alias.

`tableReferencedInAst` is deliberately the same traversal run with `dryRun`, so
`assertNoAssertionDependsOn` inherits the over-match as a **false refusal**: an
assertion whose body merely declares `with zap as (…)` blocks `drop table zap`.

## Over-match 2 — the `new.` / `old.` row-image prefix

`new` and `old` are not reserved words in this parser, so `create table new (…)`
is legal. Inside that table's own CHECK expression or a column DEFAULT,
`new.a` names **the row being written**, not the table. Renaming the table
rewrites the qualifier to the new name and the constraint stops compiling.

The column walker already handles this pair of concerns
(`matchesRowImage` / `isQualifierReboundAboveSeed`, covered by
`41.10.2-alter-drop-column-check-and-assertion.sqllogic` §13/§14). The table
walker has no equivalent.

# Design

Give the table walk the same scope discipline the column walk has, and express
both the rewrite and the read-only probe over **one** traversal so they cannot
drift (the equivalence `tableReferencedInAst`'s doc comment already commits to).

## Shape

Refactor `visitTableRename` into a scope-aware **table-reference visitor** with a
callback, and re-express the existing entry points over it:

```ts
/** Every real (non-shadowed) table reference the walk finds. `setName` is absent
 *  on a read-only walk; calling it rewrites the reference in place. */
type TableRefSink = (ref: {
    schema: string | undefined;     // as written; undefined = unqualified
    name: string;
    setName: (next: string) => void;
}) => void;

function visitTableRefs(node: AST.AstNode | undefined, sink: TableRefSink, opts: TableRefOpts): void;
```

- `renameTableInAst` supplies a sink that matches `(oldName, defaultSchemaName)`
  and calls `setName(newName)`.
- `tableReferencedInAst` supplies a sink that matches and records `true`, with an
  early-out once the answer is known (today's `dryRun` short-circuit).

Keeping one traversal is the point: the DROP guard must refuse exactly what a
rename would rewrite. A second walk, or an identity-rename trick, would break
that — see the existing comment on `tableReferencedInAst`.

## Scope frames

Reuse the shape of the column walker's `ScopeFrame`, but the table walk needs
strictly less of it. It needs the set of **bound qualifiers** in each frame:

- CTE names declared by an enclosing `with` clause, registered in the same order
  `pushWithFrame` uses today — a `with recursive` member registers its own name
  *before* its body is visited, a non-recursive member *after*.
- aliases introduced by any FROM item: `table` sources with an alias,
  `subquerySource`, `functionSource`, and both legs of a `join`.
- unaliased subquery / function sources contribute nothing.

Rules at the two match sites:

- **`case 'table'` (a FROM source).** Skip the reference when
  `ts.table.schema === undefined` and the name is a CTE in scope. A
  schema-qualified source (`main.zap`) is never a CTE and is never skipped.
  An *aliased* table source still refers to the real table — `from zap z` is a
  genuine reference and must still be rewritten. It is the source **name** that
  matters here, not the alias.
- **`case 'column'` (a qualified `q.col`).** Skip when the nearest frame that
  binds `q` binds it to something other than the renamed real table: a CTE name,
  a subquery/function alias, or an alias of a different table. `from other zap`
  followed by `zap.k` refers to `other`, not to the renamed table.
- **DML target identifiers** (`rewriteIdentifierIfTable`, reached from
  insert/update/delete). An **unqualified** target name binds the statement's own
  leading-WITH CTE when one matches — that is the planner's rule
  (`resolveCteTarget` in `planner/building/dml-target.ts`: "A CTE name shadows a
  same-named schema table / view / MV as a write target"). Mirror it: skip an
  unqualified target that names a CTE in scope; never skip a schema-qualified one.

## Row-image suppression

Add an opt-in flag on the entry points whose expression is evaluated against a
**written row**, suppressing a bare `new.` / `old.` qualifier from counting as a
table reference:

- `renameTableInCheckConstraints` — a CHECK may spell `new.a` / `old.a`.
- `renameTableInColumnExpressions` — a column DEFAULT may spell `new.a`.
- **not** `renameTableInIndexPredicates` — a partial-index predicate describes
  rows already stored and has no written-row context, so `new.x` there is a real
  three-part-free table reference. (The column walker's doc comment records the
  same asymmetry from the other direction.)

Suppression is scope-aware, mirroring `isQualifierReboundAboveSeed`: it applies
only while no inner FROM/WITH frame rebinds `new` / `old`, and never to a
schema-qualified `main.new.a`, which is a real table reference.

Note the direction is the mirror of the column walker's. There, the flag means
"treat `new.` as *my* row image and rewrite the column". Here it means "`new.` is
a row image, so do **not** treat it as a reference to a table called `new`".

# Edge cases & interactions

- **Recursive CTE self-reference.** `with recursive zap as (select … union all
  select … from zap)` — the self-reference must be skipped, which is why the
  recursive member registers its name before its body.
- **Inner WITH shadowing an outer one.** Innermost binding wins; a name bound only
  by an outer frame is still shadowed for the inner body.
- **Sibling CTE visibility.** A non-recursive member sees only *prior* siblings
  (`buildCommonTableExpr`). A `from fwd` in an earlier member where `fwd` is a
  later sibling binds the **real** table and must still be rewritten.
- **Compound / union legs and `stmt.union`.** Each leg is inside the same WITH
  frame; do not pop early.
- **`dryRun` equivalence.** After the refactor, assert in a test that the probe and
  the rename agree on every new case — one traversal is the invariant, not an
  implementation detail.
- **Frame stack unwinding on throw.** Every push needs its `finally` pop, as in the
  column walker; a leaked frame would poison later objects in the same propagation
  loop.
- **Idempotence.** `renameTableInAst` is called twice on some paths (module hook
  then propagation pass). A second call must find nothing and return `false`.
- **Case folding.** `WITH ZAP` shadows `zap`; `NEW.A` is a row image. All name
  comparisons stay case-insensitive.
- **Schema-qualified names inside a shadowed scope.** `main.zap` is never a CTE and
  never a row image — the skip rules must not swallow it.
- **`with defaults` / `with inverse` clauses on a view body.** Their exprs sit in
  the body's FROM frame; the walk already descends them and must keep the frame
  pushed while it does.
