# Why

`bench-gate-ratio-guards` gives `yarn bench:gate` a within-run ratio-guard pass. This
ticket makes the gate part of `yarn check` (the project's full pre-release verification —
there is deliberately no continuous-integration service and this adds none), adds at least
two new measured guards, and writes the documentation. Split from that ticket on a token
budget; do it after the guard engine lands.

# Edge cases to honour (from the plan)

- `yarn check` on a dirty tree is the normal dev case: the gate reports the dirty tree
  (existing gate.mjs banner) and still runs — never refuses.
- Root `build` runs `yarn clean` first, so `dist/` is fresh when the gate runs in the
  chain. A developer running `yarn bench:gate` against a stale/absent `dist/` gets an
  import error — existing behaviour of every bench entry point; say so in the docs, no new
  handling.
- The re-measure path must not double-count: one verdict, two measurements (owned by the
  prereq ticket; verify it holds end to end here).

# Validation
