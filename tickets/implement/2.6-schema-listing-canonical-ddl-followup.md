# Follow-up: finish the test sweep for canonical `schema()` DDL

## What already landed

This is a continuation of ticket `schema-listing-report-canonical-ddl` (its ticket file has been
deleted; this one carries the remaining scope forward under the same prereq relationship — there is
nothing left to depend on, the code change already happened).

In `packages/quereus/src/func/builtins/schema.ts`:

- The hand-rolled `buildIndexCreateSql` is gone. Index rows now render through
  `renderIndexCreateSql`, which calls the canonical `generateIndexDDL(index, tableSchema)`
  (no `db` argument) inside the existing try/catch-null guard.
- The plain-table branch's hand-rolled `create table "x" (...) using ...` string is gone. It now
  calls `generateTableDDL(tableSchema)` (no `db`).
- `exposedImplicitIndexes()` returns `SyntheticExposedIndex` (no `unique` flag — see
  `schema/catalog.ts` ~852). A new adapter, `syntheticExposedIndexToIndexSchema`, lifts each
  descriptor to the `IndexSchema` shape with `unique: true` before calling `generateIndexDDL` —
  these structures back UNIQUE constraints, so they are unique by construction.
- `yarn tsc -p tsconfig.json --noEmit` in `packages/quereus` is clean.
- `packages/quoomb-cli/src/commands/dot-commands.ts` `.schema` command was checked — it prints the
  `sql` column verbatim with no parsing, so it needs no change.
- `test/logic/06.3-schema.sqllogic` was updated: its four `schema().sql` index assertions now
  expect the canonical, schema-qualified form (e.g. `CREATE INDEX "idx_category" ON
  "main"."products" (...)` instead of the old `ON "products" (...)`) — confirmed against a live
  run of the new code.

not just indexes: it goes from the old one-line `create table "t" (a INTEGER, b TEXT) using
memory()` to something like `CREATE TABLE "main"."t" ("a" INTEGER NULL PRIMARY KEY, "b" TEXT NULL)
USING noalter`. Only `06.3-schema.sqllogic` (index-focused) has been swept so far. Still needed:
