# Pin the declared-form contract: tests + docs (Arms B and C of the original ticket)

Split out of `4-generated-and-default-exprs-see-unconverted-row-on-insert` (same-stage
continuation after a budget stop). That ticket makes INSERT evaluate DEFAULT and
GENERATED expressions against the converted row, so all write paths agree. This ticket
pins the contract so it cannot silently regress, and writes it down.

## Arm B — contract test

Existing coverage (checked; do not duplicate):
- `15.1.1-json-check-coercion.sqllogic` covers immediate CHECK, deferred CHECK, and UPDATE
  for JSON, and documents why the `OR REPLACE` NOT NULL DEFAULT substitution deliberately
  reads the written form and converts its own cell afterwards.
- `06.9.1-json-coerce-once.sqllogic` pins that conversion happens once.
- `test/dml-write-representation.spec.ts` pins what storage receives, not what an
  expression sees.

Genuine gaps to fill with ONE new sqllogic file stating the whole contract in one place —
every expression evaluated against a row being written sees the declared form — across
immediate CHECK, deferred (subquery-bearing) CHECK, DEFAULT, and GENERATED, for INSERT and
UPDATE, on `datetime` (the sharpest witness: `'2099-01-01T00:00:00.000Z'` converts to
`2099-01-01T00:00:00`, so a generated `text` column over a `datetime` column shows the
split immediately). Include the *agreement* assertions that actually caught the bug:
- same value INSERTed vs UPDATEd into a generated-column table yields the same computed value;
- touching an unrelated column does NOT change a computed column;
- `alter table … add column … generated` backfill equals a subsequent INSERT;
- `add column <c> <type> default (new.<col>)` backfill equals a subsequent INSERT;
- `on conflict … do update` recompute equals plain UPDATE.
Numbering: CHECK-coercion neighbour is `15.1.1`; generated columns live around `41`.
Reminder for repro tables: columns are NOT NULL by default in this engine — spell `null`.

## Arm C — docs and release note

- **`docs/types.md` § Where coercion happens**: the bullet list enumerates `emitInsert`,
  `emitUpdate`, the two post-pass single-cell injectors, and the ADD COLUMN backfill, but
  never says where DEFAULT/GENERATED evaluation sits in that order — the omission that let
  the paths diverge. State the contract positively (every expression evaluated against a
  row being written — CHECK, DEFAULT, GENERATED — sees the declared form), describe the
  INSERT pipeline's interleaved WriteCoercion step, and name the new guarding test.
- **`docs/sql-alter.md`** (~line 62): backfill/INSERT parity claim becomes true once the
  prereq lands — leave the text, ensure the new test guards it.
- **`docs/invariants.md`** — `## RT — Runtime` is "Reserved."; add the first entry (RT-001)
  stating this property, in the register's exact format (`code:` / `guard:` / `doc:`),
  naming concrete code sites; verify with `yarn docs:check`.
- **Release note** for the 4.3.1→4.4.1 change described in
  [GH #28](https://github.com/gotchoices/quereus/issues/28): an immediate CHECK used to see
  the written form and now sees the declared form; deliberate; it is what fixed
  [GH #25](https://github.com/gotchoices/quereus/issues/25) (deferred CHECK subquery
  comparing unconverted `new.<col>` against an already-converted stored value). See
  `docs/releasing.md` for placement.
