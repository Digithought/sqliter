# What landed

A fifth benchmark suite, `packages/quereus/bench/suites/store.bench.mjs`, with **eleven**
benchmarks. It calls `@quereus/store` key functions directly — no `Database`, no provider,
no query — so a regression in key building gets its own number instead of showing up as
"the full scan got slower".

| Benchmark | What it times | Median (this machine) |
| --- | --- | --- |
| `data-key-int` | `buildDataKey` over one bigint column | 347 µs |
| `data-key-text-binary` | one 34-byte text column, `BINARY` | 503 µs |
| `data-key-text-nocase` | the same text under `NOCASE` (routes through a key normalizer) | 545 µs |
| `data-key-text-astral` | the same text plus four astral-plane characters | 775 µs |
| `data-key-json` | a plain object through the generic OBJECT path (canonical JSON) | 1.08 ms |
| `data-key-blob` | 34 raw bytes with two escape-triggering bytes — added in review | 199 µs |
| `data-key-asc-2col` | `[bigint, text]` ascending — the control for the row below | 871 µs |
| `data-key-desc-2col` | the same two columns descending (encoder bit-inverts every byte) | 936 µs |
| `data-key-composite-4col` | `[bigint, text, real, null]` | 1.52 ms |
| `index-key-text-int` | `buildIndexKey` — index half plus PK half | 990 µs |
| `decode-composite-4col` | `decodeCompositeKey` over the 4-column key | 1.54 ms |

Every figure is **1 000 key builds, not one** (`KEYS_PER_CALL`), shared across every entry
so the shapes stay comparable. `setup` round-trips every distinct fixture row through
encode/decode and throws on mismatch; `fn` asserts only the total encoded byte length
(cheap enough not to swamp the encode), except `decode-composite-4col`, where the decode is
the subject and `fn` asserts value equality per column.

Also landed: the accepted-tradeoff `NOTE:` at the top of `bench/apply-schema-unchanged.mjs`
recording that it stays ad hoc by decision, and the `docs/benchmarking.md` §
*The `store` suite* section plus the counts, counters-qualification table and `skip()`
section it touches.

## How to check it

```
cd packages/quereus
yarn bench --filter store/          # 11 rows, ~16 s
```

# Review findings

the handoff that could be tested was tested rather than taken on trust; the ones that held

## Fixed in this pass

- **`docs/architecture.md` § Benchmark Suite was left stale.** It still said "46 benchmarks"
  and "46 benchmarks from 27 workloads", and listed only "parser, planner, execution, and
  mutation". The change added a suite and never touched that file. Updated to 57 benchmarks
  from 38 entries, with a sentence saying the `store` suite is deliberately outside the
  storage-backend dimension. This is the second doc that carries a benchmark count; both now
  agree.

- **No BLOB coverage — one of the five storage classes had no row, and the suite's own
  helper carried dead code for it.** `sameValue`'s `Uint8Array` branch and `describeValue`'s
  `blob(...)` branch were unreachable: no fixture in the suite was a blob. That is a real
  coverage gap rather than a style point — a column *declared* `json` keys through the BLOB
  path (its key transform maps the value to a `Uint8Array` before encoding), so the suite
  priced the OBJECT path an undeclared `any` column takes while missing the path a declared
  `json` column actually uses. Added `data-key-blob`: 34 bytes, matching a text fixture's
  byte count, with an embedded `0x00` and `0x01` so the shared escape scheme is exercised
  rather than a plain copy. The round trip passes, so the escape path is also now verified
  on every run.

- **The `skip()` body was written out three times**, once per benchmark factory, all
  identical. Replaced with one `skipUnlessStoreLoads` shared by every entry. Re-verified for
  real, not reasoned about: renaming `packages/quereus-store/dist/src/index.js` away
  produced `skipped — @quereus/store is not usable here (...)` and enumeration still
  reported "selected 1 of 57 benchmarks", so no static store import leaked in. File restored
  in the same command.

- **A comment stated the surrogate fast path backwards.** `ASTRAL_TEXTS`' doc said
  `findUnpairedSurrogate`'s `HAS_SURROGATE` "fast-path test FAILS" for astral text. The
  regex `/[\uD800-\uDFFF]/` *matches* astral text — it is the early `return -1` that is
  skipped. A reader checking the source against the comment would have found them
  contradicting. Reworded.

- **`docs/benchmarking.md` misattributed the 21 blocking type errors to "the other four
  suites".** Re-measured: they are in three files (`planner` 10, `execution` 6, `mutation`
  5); `parser.bench.mjs` is clean. Corrected, and pointed at the new ticket.

- Counts updated everywhere the new benchmark moved them: 56 → 57 benchmarks, 37 → 38
  entries, `store` 10 → 11 in both the suite table and the counters-qualification table,
  wall-clock ~15 s → ~16 s, and the "failing all ten" phrasing in the `skip()` section.

## Appended as evidence to an existing ticket

- **`debt-store-share-utf8-codecs`** gained a second measurement arm. The new `data-key-blob`
  row makes the encode side legible for the first time: the same 34-byte payload costs
  ~200 ns per key as raw bytes and ~503 ns through `encodeText`, so the whole UTF-8 step is
  roughly 300 ns of a ~500 ns text key build. Written into that ticket with the caveat it
  needs — that figure bundles the surrogate scan, the `new TextEncoder()`, the conversion
  and the normalizer resolution, and does **not** isolate the allocation's share. It matters
  because that ticket's `tradeoffs` line says a maintainer could reasonably call the saving
  noise; the encode side is now shown to be the expensive half, and `encodeText` belongs in
  its sweep alongside `decodeText`. No new ticket — this is the Nth instance of a class that
  already has one.

## Considered and declined

- **`bench/apply-schema-unchanged.mjs` staying outside the suites** carries an
  accepted-tradeoff `NOTE:` added by this change, with its reasoning and its successor ticket
  (`feat-bench-apply-schema-fastpath-guard`, already in `backlog/`). Left alone — the call
  was made and nothing has changed since.

- **`buildDataKey` is a one-line delegation to `encodeCompositeKey`**, so eight of the eleven
  rows are, strictly, timing `encodeCompositeKey`. Not filed: `buildDataKey` is the name
  production code calls and the one whose signature would change, so binding the benchmark to
  it is correct even though the body it reaches today is a pass-through.

- **`INTEGERS` never exceeds 2^53** (largest fixture is 13 × 1 000 000 007), so
  `encodeNumeric`'s non-zero-residual tie-break branch — the one that exists for int64s past
  the double's exact range — is never exercised. Not filed as a gap: the branch costs the
  same fixed 17 bytes and the same two `DataView` writes either way, so a benchmark over it
  would report the same number. Worth knowing if that encoding ever becomes variable-width.

## Checked and clean

- **Round-trip correctness of every fixture.** Read `encodeCompositeKey`, `decodeCompositeKey`,
  `encodeNumeric`/`decodeNumeric`, `encodeText`, `encodeObject`/`decodeObject` and
  `buildIndexKey` against each `decodesTo`. The DESC un-inversion is exact for the reason
  stated (all-or-nothing directions), the index key's two halves genuinely decode as one
  composite because `encodeCompositeKey` is a plain concatenation of self-delimiting column
  encodings, and the JSON fixture's `decodesTo` key order matches the canonical string's.
  All eleven `setup` round trips pass at run time.
- **Measurement validity.** No `fn` allocates its fixture; results feed a checked sum so
  nothing is dead-code-eliminated; `KEYS_PER_CALL` is one constant across every shape.
- **Type cleanliness of the new file** under `strict` + `checkJs` — re-verified after the
  review edits, via a scratch config deleted in the same command. Zero errors attributed to
  `store.bench.mjs`.
- **Enumeration safety.** The suite reaches `@quereus/store` only through
  `bench/lib/store-counters.mjs`'s single cached dynamic import; verified by the skip-path run
  above, which still enumerated all 57 benchmarks with the store dist missing.
- **Resource handling.** Nothing here opens a database or a provider, so there is nothing to
  leak; `teardown` releases the fixture arrays and the module reference.
- **Docs.** Every file the change touched was read, plus the two it should have touched
  (`docs/architecture.md`, found stale — fixed above; `packages/quereus/README.md`, which
  carries no benchmark counts and needed nothing). A repo-wide grep for benchmark-count
  phrasings now finds only the two corrected sites.
