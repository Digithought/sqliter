# `41.2.3` § 12 no longer needs standalone index DDL

## What shipped

`41.2.3-alter-column-set-not-null-pk-backfill.sqllogic` § 12 used a standalone `create index`,
which needs the `standalone-index-ddl` capability the file never declared — so on a backend
without that feature all twelve sections died at one statement.

- § 12 now reaches a secondary index through a table-level `y integer null unique` column, so
  the file declares no capability and runs everywhere. Statement sequence and expected rows are
  unchanged.
- New sibling `41.2.3.1-alter-column-set-not-null-pk-backfill-secondary-index.sqllogic` declares
  `-- requires-capability: standalone-index-ddl` and keeps the original `create index` form,
  following the carve-out precedent of `06.9.1.1-json-coerce-once-index` and
  `10.1.2.1-add-constraint-in-transaction`.
- No harness bookkeeping changed: both files run on both backends, and the new file's subject is
  a primary-key re-key rather than index DDL, so it belongs in neither `MEMORY_ONLY_FILES` nor
  `logic-capabilities.spec.ts`'s `subjectFiles`.

## Review findings

### Verified, not taken on trust

The implementer flagged that they had not re-derived the ticket's `query_plan()` evidence. Both
load-bearing claims were re-checked in this pass with a throwaway `.sqllogic` probe (since
deleted; working tree clean):

- **`unique` really produces an index seek.** `query_plan()` for `select x, y from t_probe where
  y = 1` over `create table t_probe (x integer null default 7, y integer null unique)` returns
  `INDEXSEEK | INDEX SEEK t_probe USING _uc_y` — not a table scan. The rewritten § 12 is
  therefore not vacuous: a stale index entry after the re-key still fails it.
- **`unique` does not steal the primary key.** `findPKDefinition`
  (`packages/quereus/src/schema/table.ts:1215-1250`) consults only a column-level or table-level
  `PRIMARY KEY`, then falls back to the all-columns key. A `unique` constraint is never read, so
  `t_bf13` keeps its `(x, y)` key and the backfill still moves key values — the thing § 12 tests.

### Fixed in this pass (minor)

- **Parent file did not point at its carve-out sibling.** Both existing precedents do
  (`10.1.2-ddl-in-transaction` names `10.1.2.1` three times; `06.9.1-json-coerce-once` names
  `06.9.1.1` twice) — a reader of § 12 otherwise cannot find where the `create index` shape went.
  Added two lines to § 12's prose comment naming `41.2.3.1`. Kept the directive name
  backtick-quoted so `NEAR_MISS_RE` does not fire; the capability corpus sweep confirms the file
  still parses.

### Filed as a new ticket (major)

- **Nothing checks that a `.sqllogic` file declares the capabilities it uses, and three more
  files are wrong today.** The implementer's own gap note wondered whether the pattern was
  systemic; it is. Measured with
  `grep -rlniE "^\s*(create (unique )?index|drop index)" packages/quereus/test/logic/*.sqllogic`
  against `grep -rln "requires-capability"` over the same set: 54 files use standalone index DDL,
  51 declare it, and `03.6-type-system`, `11.3-index-nested-loop-join` and `15.1-semantic-ordering`
  do not — each the same defect `41.2.3` just had.

  Filed as `tickets/backlog/debt-sqllogic-capability-declaration-guard.md` rather than three point
  fixes: the root cause is that declaration is voluntary and unverified. `logic-capabilities.ts`
  validates a directive that is *present*, and `logic-capabilities.spec.ts`'s `subjectFiles` is a
  hand-maintained list of files someone remembered — which by construction cannot catch a file
  nobody remembered. A corpus sweep asserting "file uses index DDL ⇒ file declares the token"
  retires the whole class, and the three offending files are its first customers. (Checked the
  board first: three open tickets mention `03.6-type-system.sqllogic`, all about numeric text
  coercion — none claims the capability-declaration site.)

### Checked and clean

- **Docs.** `packages/quereus/test/README.md` § `-- requires-capability:` already prescribes
  splitting a file when only part of it needs a capability — this change is that prescription
  applied, so no edit is owed. `docs/schema.md:59` names `41.2.3` as the cross-backend pin for
  the key-re-key rule; still accurate, and the sibling pins the same rule, so no edit there
  either. No other file in `docs/` or `test/*.ts` references `41.2.3`.
- **Section semantics.** § 12's header prose ("a SECONDARY INDEX over an untouched column") still
  describes the rewritten section: `y` remains untouched, `x` is the altered column. The two
  files both define `t_bf13`, which is safe — each `.sqllogic` file runs against its own database.
- **Harness bookkeeping.** Confirmed the two skipped list-edits were genuinely correct, not
  overlooked: `logic-capabilities.spec.ts`'s `subjectFiles` names files whose *subject* is index
  DDL, and the two prior carve-outs (`06.9.1.1`, `10.1.2.1`) are likewise absent from it.
- **Tripwires.** None recorded. Nothing here is of the "fine now, matters if X grows" shape — the
  one conditional-looking concern (the corpus sweep) is a defect today, not a future one, so it
  became a ticket.
