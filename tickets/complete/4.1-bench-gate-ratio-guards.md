# What landed

`yarn bench:gate` gained a second pass. After the work-counter comparison it times every
benchmark named by a suite's `ratioGuards` export — one fork per benchmark, the same
isolation `yarn bench` uses — and fails when one benchmark's median exceeds its declared
bound against another's **in the same run**. A within-run ratio cancels machine speed,
which is what makes it gateable when an absolute millisecond figure is not.

Noise protection: the first timing uses a reduced calibration profile (`GATE_CALIBRATION`,
100 ms warmup / 300 ms target / 1500 ms cap, against the manual runner's 250/1000/5000). A
guard that fails at reduced calibration is re-measured once at **full** calibration before
it may fail the run, and the re-measure decides — so a noisy machine costs a wasted
re-measure, never a false failure. Both measurements come back as ONE verdict record.

`--report-only` (env: `QUEREUS_BENCH_GATE_REPORT_ONLY`) reports every finding but exits 0;
it is refused alongside `--accept`, and the `--json` `failed` field stays honest either
way. All decision logic is pure functions in `bench/lib/guards.mjs`; `gate.mjs` holds only
process wiring.

# Review findings

Reviewed the three implement commits (`e38b8f4e6`, `fa879a851`, `58891f51b`) against
`8d13dc9c3` before reading the handoff.

## Checked and clean — no finding

- **The re-measure fold.** Traced every combination: a shared member across a failed and a
  passing guard, a member that skips only on the second fork, a member whose second fork
  dies. `mergeRemeasuredVerdicts` replaces only initially-`failed` verdicts, and both
  members of any such guard are always in the retry set, so no verdict can be decided from
  a mix of reduced- and full-calibration medians. The length-divergence throw is a real
  guard, not decoration: the two `checkRatioGuards` calls share one suite array.
- **The member-fork-failure path.** A dead fork deletes its `allBenchmarks` entry (so a
  stale reduced median cannot be re-read as the full one), the guard reads *not evaluated*,
  and a separate counter fails the gate. Correct by reading; see the untested-wiring note
  below.
- **Degenerate medians.** Zero/zero to 1, nonzero/zero to Infinity. Neither can produce a
  `NaN` that compares false against every bound and passes forever. Covered by tests.
- **Ordering of the verdict cases** (informational, then skipped, then unselected, then
  failed-to-run): each earlier case would be masked by a later one, and the tests pin the
  ordering.
- **Temp-directory sweep and signal handlers.** `sweepBenchTempDirs` only removes
  directories whose owning PID is dead or force-listed, so the gate's own in-process
  counters pass cannot have its working directories swept out from under it.
- **`--accept` interaction.** The guard pass never runs in accept mode; `ratio_guards` is
  `null` there rather than `[]`, which is the honest distinction ("not evaluated" versus
  "no guards"). `--report-only` is refused with `--accept`, and the env var is ignored
  there.
- **`QUEREUS_BENCH_LEVELDB` deletion** happens before `loadSuites` and therefore before any
  fork, so guard-member children inherit the cleared environment too.
- **`run.mjs` de-duplication.** The guard logic moved to `bench/lib/guards.mjs` with no
  behavioural change at the `run.mjs` call site; both entry points now share one
  implementation, which is what the module comment claims.

## Minor — fixed in this pass

- **A `--filter` that selects only one member of a guard forked the other one for nothing.**
  Measured: `node bench/gate.mjs --filter correlated-subquery` spent 1.1 s timing
  `execution/correlated-subquery` for a guard that was then reported *skipped* — the
  verdict is decided by the selection, before anything is timed. `guardMemberNames` now
  takes an optional selected-name set and drops a guard with an unselected member the same
  way it already drops one naming an informational row; `gate.mjs` passes the selection.
  Re-ran the same command: no fork, same verdict, same exit code. Three tests added.
- **Failing and passing verdicts printed ratios at different precision** — `toFixed(1)` on
  failure against `toFixed(2)` everywhere else. `maxRatio` below 1 is a legal "must stay
  faster than" guard, and one decimal renders such a failure as `1.0x (max 0.5x)`, hiding
  which side of the bound the run landed on. Both details now use the existing `fmtRatio`
  helper, which is the one place the precision rule lives. Existing assertion updated, one
  test added for the sub-1 case.
- **Docs "Where the code lives" did not mention the new code.** Added the
  `bench/lib/guards.mjs` row, added `test/bench-guards.spec.ts` to the harness-tests list,
  and corrected the `bench/gate.mjs` row, which still described a single counters pass.
- **The guard's own comment block in `execution.bench.mjs` gave stale tuning advice** —
  "raise `CALIBRATION.targetTotalMs`" was written before the gate had a second profile. It
  now names both `CALIBRATION` and `GATE_CALIBRATION` and says which command uses each.

## Major — appended as an arm to an existing backlog ticket, not filed fresh

The site-claim grep found `debt-bench-harness-self-test` already owns both halves of this
class, with per-review re-measured numbers. Appending was correct; a fresh ticket would
have been the fourth on the same root cause.

- **`bench/*.mjs` is checked by nothing.** `packages/quereus`'s eslint globs only
  `src/**/*.ts test/**/*.ts`, and `tsconfig.test.json` includes `bench/lib/**` but not
  `bench/*.mjs` — so the ~250 new lines of wiring in `gate.mjs` were verified only by
  `node --check` and by running the gate. Measured by copying `tsconfig.test.json` to a
  scratch config with `bench/*.mjs` added and running `npx tsc --noEmit`: **180 errors**
  (`run.mjs` 91, `gate.mjs` 80, `child.mjs` 9). Every one read was an annotation gap —
  implicit-`any` parameters, property access on untyped `object` bags, two `WriteStream`
  file-descriptor narrowing complaints from the `--json` stream swap. **No real defect
  among them**, so this stays debt rather than becoming a bug. Scratch config deleted.
- **The gate's guard wiring has no automated coverage** — the fork helper, the 120 s
  timeout and 5 s reap backstop, the signal handlers, the member-fork-failure path, and the
  zero-counter-selection relax (which is unreachable today, since both members of the only
  guard declare `counters()`). Same blocker that ticket already names: the suites directory
  is not a parameter, so a misbehaving fixture suite cannot be pointed at without writing
  into the real `bench/suites/`.

## Conditional — recorded as a tripwire, not a ticket

- **A pinned benchmark ignores `GATE_CALIBRATION` entirely.** `pinnedPlan` reads its counts
  off the benchmark, so `--gate-calibration` is a no-op for one; the re-measure then becomes
  a second independent sample rather than a longer one. It still breaks a one-off noise
  spike, but does not narrow the distribution the way the design comment implies. No
  benchmark pins itself today. Parked as a `NOTE:` beside `GATE_CALIBRATION` in
  `bench/lib/calibrate.mjs`, where whoever writes a guard over a pinned benchmark will meet
  it.

re-measure-decides design absorbs that (a noisy re-measure can only false-PASS), which is
the right way round.
