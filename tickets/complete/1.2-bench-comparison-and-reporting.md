# What landed

## Environment capture (`bench/lib/environment.mjs`)

Every results file carries an `environment` block: CPU model, logical core count, total
memory, platform, OS release, architecture, Node version, V8 version, commit hash, and a
tri-state `dirty` flag for the working tree (`true` / `false` / `"unknown"` outside a git
checkout). `commit` and `node` are also lifted to the top level, derived from the same
capture rather than read twice.

Both git lookups go through one helper that returns `null` on any failure, with
`windowsHide: true`, a 5 s timeout, and (added in review) `cwd` pinned to the module's own
directory. Outside a checkout the harness still runs.

`compareEnvironments()` reports material differences only: CPU model, core count, platform,
architecture, Node **major** version. OS point release and memory are recorded but not
warned about. A baseline with no `environment` block is itself reported as a mismatch.

## Noise-aware comparison (`bench/lib/compare.mjs`; the floor lives in `stats.mjs`)

```
noiseFloor% = max(5, sqrt(currentSpread² + baselineSpread²))
```

Verdicts: `no-change` (within the floor), `regression` (clears the floor **and** >10%, red,
gates), `improvement` (mirror image, green), `changed` (clears the floor, under the 10%
minimum — printed plainly, never gated). The floor prints in a `Noise` column beside every
delta.

A benchmark unstable in **either** run is never gated; its delta still prints and its row
says `not gated`. A baseline median that rounds to zero yields no delta rather than
`Infinity`. A baseline entry with no `spread_pct` gets `ASSUMED_SPREAD_PCT` (20%) and the
banner says how many entries needed it.

`compareRun(rows, baselineBenchmarks, filter)` is pure — nothing in it prints or touches
the filesystem.

## Four non-delta outcomes, plus a counted summary

`new`, `missing`, `filtered` and `failed`. Every name in either run appears exactly once.
The summary counts all nine statuses and names each excluded benchmark.

## Ergonomics

- `--baseline latest` resolves the newest file in `bench/results/` during argument
  handling, before this run writes its own. Lexicographic sort on ISO-timestamp filenames,
  deliberately not mtime.
- `--json` moves every human line to stderr and writes the result object to stdout, last.
- ANSI suppressed whenever the human stream is not a TTY; padding happens before colouring.
- `checkRatioGuards` returns verdict records, `reportRatioGuards` prints them; the verdicts
  land in the JSON as `ratio_guards`.

## Rounding precision

`round()` rounded every duration to the microsecond, so a 4 µs parser median could only
move in 25% steps — enough to manufacture a gated regression out of rounding alone.
Precision raised to nanoseconds (`PRECISION = 1e6`); percentages keep a coarser
`PERCENT_PRECISION = 1e3`. The table's µs format gained one decimal for the same reason.

# Review findings

## Blocking defect found and fixed: `yarn lint` was broken

**`yarn lint` failed at the handed-off commit.** `packages/quereus`'s lint script ends in
`tsc -p tsconfig.test.json --noEmit`, and that config includes `bench/lib/**/*` with
`checkJs` on. The two new modules produced **25 type errors** (13 in `compare.mjs`, 12 in
`environment.mjs`) — JSDoc `@param {object}` bags reached into for `median_ms`,
`spread_pct`, `stable`, `node`; `@param`s with no type at all; `MATERIAL_FIELDS` indexed by
a `string`; an `execSync` options literal that did not match `ExecSyncOptions`. The
handoff flagged that lint had not been run; it had been broken by the change.

Fixed by typing the modules properly rather than by widening to `any` (AGENTS.md: *no
`any` — type it right*), which is also the fix that retires the class:

- `stats.mjs` now exports two typedefs — `BenchmarkSummary` (what `summarize` writes) and
  `BaselineEntry` (`Partial<BenchmarkSummary>`, what a possibly-old results file yields).
  Separating the write shape from the read shape is what stops the next consumer assuming
  a field an old file does not carry; the `object` bags could never have expressed that.
- `compare.mjs` consumes both, plus a `RunRow` typedef for what `runSelected` hands it.
- `environment.mjs` gains `Environment` / `RecordedEnvironment` and types every exported
  function's parameters.

`yarn lint` now exits 0.

## Test coverage: two new modules shipped with none

`compare.mjs` documents itself as "pure functions … so the rules are testable without
running a benchmark", and then nothing tested them. The handoff's `--grep "bench/lib"` run
of 45 tests was entirely the pre-existing calibrate/stats specs; not one line of
`compare.mjs` or `environment.mjs` was executed by `yarn test`. These rules decide whether
`yarn bench` exits zero, and `yarn bench` is not part of `yarn test`, so the only thing
checking them was a person reading a table.

Added `test/bench-comparison.spec.ts` — **49 tests**, taking the suite from 45 to 94 for
`bench/lib`. Coverage by promise, not by function:

- **Noise floor** — quadrature not summation, the 5% minimum, assumption in either
  argument position, and non-finite spreads not poisoning the floor.
- **Delta classification** — both directions, the exact-floor and exact-gate-minimum
  boundaries, and the case the floor exists for (a high floor vetoing a delta that would
  otherwise gate).
- **Stability** — `stable` outranking a flatteringly tight `spread_pct`, the spread
  fallback and its exact threshold, and an old-format entry with neither field.
- **Verdicts** — regression gates, improvement does not, unstable in this run / the
  baseline / both is excluded *and names which*, a zero baseline median emits no delta.
- **Non-delta outcomes** — new, missing, failed-not-missing, failure with no detail, and
  `filtered` vs `missing` including a case that pins the shared substring semantics (a
  filter matching mid-name must not read as a deletion).
- **Summary integrity** — every name appears exactly once, the counts cover all nine
  statuses including zeros, the counts sum to the number of comparisons, and only the
  regression is gated.
- **JSON safety** — a regression test mirroring the existing `summarize` one: no
  `delta_pct` or `noise_floor_pct` is ever non-finite.
- **Environment** — capture shape and tri-state `dirty`, self-comparison raising nothing,
  each material field reported individually and all at once, OS point release and memory
  correctly ignored, Node minor ignored / major reported, absent fields reported rather
  than read as matches, and the two describe helpers.

## Defects fixed inline

- **Unrounded percentages in the results JSON.** `delta_pct` and `noise_floor_pct` were
  written at full float precision (`11.11111111111111`, `20.223748416156685`) into the same
  file whose spreads are deliberately rounded to three decimals by `PERCENT_PRECISION` —
  the constant the same commit introduced to stop exactly this. Both now round through it.
- **Two definitions of what `--filter` means.** `compare.mjs` re-implemented
  `fullName.includes(filter)` rather than calling the selector's. Two copies agree until
  one grows a glob, at which point the comparison starts reporting narrowed runs as
  deletions. Extracted `matchesFilter` in `discover.mjs`; both callers use it, and a test
  pins the agreement.
- **`git` ran in the process's working directory.** Launching the harness by absolute path
  from inside another repository recorded *that* repository's commit against these timings.
  `cwd` is now the module's own directory, so the checkout reported is the one being
  benchmarked.
- **The `filtered` list drowned the summary.** The handoff asked a reviewer to check this;
  it does. `--filter parser/` against a full baseline printed 23 consecutive lines each
  repeating the identical sentence, pushing the actionable lines off screen. Every name is
  still listed — dropping them would make a narrowed run indistinguishable from a deletion
  — but they now share one wrapped block (23 lines → 8). `unstable`, `new` and `missing`
  keep a line each, because each carries a *different* reason.

## The headline concern: the acceptance criterion, and where it went

The handoff's most important point stands and is correct. The floor is built from
**within-run** spreads and is therefore blind to **between-run** displacement: two full
27-benchmark runs minutes apart on an unchanged tree gated two regressions whose spreads
were 3-6% in *both* runs — a narrow distribution around a centre that had moved. The
implemented rule is the specified rule and is a strict improvement on the flat 20%, but it
cannot be wired to a build gate on a loaded machine.

Disposition, deliberately *not* a new ticket: the decision belongs to
`plan/4-bench-regression-gate`, which already plans to gate on work counters and within-run
ratios rather than wall-clock, for precisely this reason. The measurement is now recorded
in three places so nobody rediscovers it:

- an **arm appended to `plan/4-bench-regression-gate`** with the evidence and the three
  candidate fixes (median-of-N-runs, common-mode subtraction, reproduce-twice),
- a **`NOTE:` on `noiseFloorPct`** in `bench/lib/stats.mjs`, at the exact site,
- a paragraph in **`docs/benchmarking.md` § Noise floor** telling a reader to treat a red
  result on a busy machine as a prompt to re-run.

## Runtime paths the handoff flagged as unexercised — now exercised

Verified with a temporary two-benchmark probe suite (one working, one throwing), deleted
afterward along with the results files it produced:

- **A failing benchmark under `--baseline`** reports as `failed`, not `missing`
  (`counts.missing` was 0), carries its reason into the comparison note, prints its stack,
  and exits 1.
- **`--json` with a failure** puts exactly one parseable object on stdout, written after
  the failure report; keys `timestamp, commit, node, environment, wall_clock_ms, benchmarks,
  failures, ratio_guards, baseline, comparison`, with the `failed` verdict and the real
  environment block present.
- **`--filter` + a full baseline** populates the `filtered` bucket with 23 entries — which
  is how the summary-drowning defect above was found and confirmed fixed.

## Checked and found sound — no change made

- **Exit-code contract.** Ratio-guard failures, gated regressions and benchmark failures
  each set exit 1 independently and none short-circuits the others; the JSON is written
  last so a crash leaves stdout empty rather than half an object.
- **`--baseline latest` resolution order.** Resolved during argument handling, before this
  run writes its file, so `latest` cannot resolve to the run's own output. The
  lexicographic-not-mtime choice is correct for the ISO-timestamp filenames and commented
  at the sort.
- **Ordering of the unstable check against the zero-median check.** The zero-median guard
  runs first, so a degenerate baseline never divides.
- **`seen.add` before the failure branch** in `compareRun` — a failed benchmark present in
  the baseline reports once as `failed`, never also as `missing`. Covered by a test now.
- **Colour handling.** Padding before colouring is correct in every cell; ANSI is
  suppressed on both streams when not a TTY.
- **Old-format baselines.** Compared without crashing; the missing-environment banner and
  the assumed-spread note both fire. The large deltas seen against the oldest files in
  `bench/results/` were checked and are the batching change from `bench-adaptive-sampling`
  (those files carry no `batch`/`samples` fields at all), not a defect here.

## Categories with nothing to report, and why

- **Resource cleanup** — untouched by this change. The signal handlers, the SIGKILL
  backstop and the `settle` guard against a double-resolve are all pre-existing and were
  re-read without finding a leak on the paths this diff added.
- **Pre-existing test failures** — none. `yarn test` is green across the monorepo;
  `tickets/.pre-existing-error.md` was not written.
- **Docs out of date** — every file the change touched was read. `docs/benchmarking.md`
  and `docs/architecture.md` § 5 were accurate as written; both gained the between-run
  limitation, and `benchmarking.md` gained the compacted-`filtered` behaviour and the
  `matchesFilter` responsibility in its file table. `yarn docs:check` passes.

## Tripwire noted, not fixed

- **`bench/run.mjs` is 727 lines** (was 522 before this ticket; `wc -l`). Roughly 250 of
  them are pure presentation — `printTable`, the `fmt*` helpers, `paintDelta`,
  `tableLegend`, the two `printComparison*` functions, `reportRatioGuards`,
  `reportFailures` — which would extract cleanly into a `bench/lib/report.mjs` owning the
  output stream and colour state that are module-level mutable globals today. Left alone:
  the extraction is mechanical but it is a 250-line move made during a review pass, and
  `plan/4-bench-regression-gate` will rewrite most of this reporting surface anyway.
  Recorded here rather than as a ticket because it is conditional — if that ticket does
  *not* restructure the reporting, the split is worth doing on its own.
