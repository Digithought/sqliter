## 4. Decisions waiting on you

1. **DATETIME has no settled canonical spelling.** `bug-datetime-literal-with-timezone-never-matches`
   cannot be fixed without deciding what the stored spelling is and whether `datetime` denotes a fixed
   instant or a time-zone-naive wall-clock value. That is a semantics decision, not an implementation
   one — it arguably belongs in `blocked/` rather than `backlog/`. **Your call; I did not move it.**

2. **`.tmp/` scratch files.** `debt-gitignore-tmp-scratch-dir` is a one-line change blocked on a
   question only you can answer: three `.tmp/` files are already committed — delete them or relocate
   them?

3. **Are tag changes structural?** `bug-alter-table-schema-event-contract-unmet` arm B assumes
   `set/add/drop tags` should raise a schema-change event. If the answer is no, the fix is a
   documentation change instead. Nothing in the docs currently says.

4. **Two `Database` objects over one storage module.**
   `bug-schema-change-not-propagated-to-other-connections-catalog` is a real wrong-result, but nothing
   in the engine claims to support that configuration. Build cross-connection catalog invalidation, or
   document the configuration as unsupported?

5. **Shared root cause, two tickets, deliberately left apart.**
   `bug-store-committed-ref-sees-uncommitted-rows` (a correctness hole in the documented
   `committed.<table>` qualifier) and `feat-store-committed-snapshot-reads` (the concurrent-read
   feature) both bottom out in `StoreModule.connect` returning a shared cached `StoreTable` that drops
   per-connection options. I did not merge them — one is a bug in a shipped feature, the other is new
   capability — but fixing `connect` twice would be waste. Noted in the bug's `tradeoffs:` line.

6. **`debt-oversized-source-files` is one ticket carrying nine splits plus a proposed build guard.**
   That is deliberate — the nine were filed one at a time, which is itself the argument for a ratchet —
   but it should probably be promoted as *the ratchet first*, with the splits drawn off individually.
   If you would rather keep the splits as separate queue entries, say so and I will unfold them.

7. **`execution_trace()` — fix or delete?** It deadlocks on every call and `row_trace()` already does
   nearly the same job. Deleting it is cheaper than re-plumbing it around the execution mutex.
