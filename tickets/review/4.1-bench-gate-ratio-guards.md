# What landed

`yarn bench:gate` now has a second pass: after the work-counter comparison, it times
every benchmark named by a suite's `ratioGuards` export — one fork per benchmark, same
isolation as `yarn bench` — and fails when one benchmark's median exceeds its declared
bound against another's **in the same run**. A within-run ratio cancels machine speed,
which is what makes it gateable when an absolute millisecond figure is not.

Noise protection: the first timing uses a reduced calibration profile
(`GATE_CALIBRATION`: 100 ms warmup / 300 ms target / 1500 ms cap, vs the manual
runner's 250/1000/5000). A guard that fails at reduced calibration is re-measured once
at **full** calibration before it may fail the run — the re-measure decides, so a noisy
machine costs a wasted re-measure, never a false failure. The two measurements come
back as ONE verdict record showing both ratios.

`--report-only` (or env `QUEREUS_BENCH_GATE_REPORT_ONLY`) reports every finding but
exits 0; refused alongside `--accept`; the JSON output keeps `failed` honest either
way. All decision logic is pure functions in `bench/lib/guards.mjs`; `gate.mjs` holds
only process wiring (fork, signal handlers, temp-dir sweep, printing).

# How it was validated

- `yarn workspace @quereus/quereus lint` — green (eslint + `tsc -p tsconfig.test.json`,
  which type-checks `bench/lib/**` and the new spec).
- `yarn workspace @quereus/quereus test` — 9971 passing, 25 pending, 0 failing;
  includes the new `test/bench-guards.spec.ts` (32 tests, no benchmark runs).
- Smoke, three runs of `node bench/gate.mjs` from `packages/quereus`:
  - `--filter execution/` — guard evaluated for real: both members forked at reduced
    calibration (~1.1 s each), ratio 1.00× vs max 10×, exit 0.
  - `--filter correlated-subquery` — baseline excluded by the filter → verdict
    `skipped ... not selected by --filter`, exit 0.
  - scratch edit `maxRatio: 0.5` + `--report-only` — reduced-calibration failure fired
    the re-measure (both members re-forked at full calibration, 26 samples vs 8),
    merged verdict printed both ratios, GATE FAILED block + REPORT-ONLY box, exit 0.
    Edit reverted; `git diff` clean afterwards.

# Reviewer starting points (honest gaps)

- **`gate.mjs` itself has NO static validation.** The package lint globs only
  `src/**/*.ts test/**/*.ts`, and `tsconfig.test.json` includes `bench/lib/**` but not
  `bench/*.mjs` — so the ~250 lines of new wiring in `gate.mjs` (fork helper, timeout /
  reap backstop, signal handlers, exit folding) were checked only by `node --check` and
  the three smoke runs above. The prior ticket text claimed eslint covers it; that was
  wrong. Consider whether `bench/*.mjs` should join a lint/type pass — that's a
  one-line glob change but belongs with `bench-gate-check-wiring`'s doc/wiring scope.
- **`GATE_CALIBRATION` values (100/300/1500 ms) are chosen, not measured.** One data
  point from the smoke runs: reduced-calibration spreads were 1.2–6.9 %; the
  full-calibration re-measure showed 10–12 % spread on a loaded machine — i.e. full
  calibration is not automatically quieter under load. The re-measure-decides design
  absorbs this (a noisy pass costs a re-measure, and a noisy re-measure can only
  false-PASS, never false-fail), but a reviewer may want one timed gate run of their
  own to sanity-check.
- **The guard pass in `gate.mjs` has no unit coverage** — it is process wiring; the
  logic it drives lives in `lib/guards.mjs`, which has the 32-test spec. The smoke runs
  are the only end-to-end exercise (they did cover ok / skipped / fail→re-measure →
  report-only paths).
- Untested corners of the wiring specifically: the 120 s child timeout + 5 s reap
  backstop, SIGINT/SIGTERM handlers, the member-fork-failure path (fork fails →
  `allBenchmarks` entry deleted → gate fails with "guard member benchmark(s) failed to
  run"), and the zero-counter-selection relax (a `--filter` matching only guard members
  must still run the guard pass).
