# What was built

`yarn bench:gate` re-runs every counter-declaring benchmark (56 run, 19 LevelDB rows
always skip) in **one process**, compares each counter block for exact equality against
`bench/reference/<suite>.json`, and exits non-zero on any difference. `yarn bench:accept
--reason "<why>"` re-measures and rewrites only the reference files whose contents changed,
recording provenance (commit, date, node, platform, git user, reason). Nothing about
wall-clock is measured or gated — that half is the follow-on ticket
`bench-gate-ratios-and-check` (already in implement/).

Design details are in `docs/benchmarking.md` § *Regression gate*; the implement ticket's
full rationale (measurements, cost tables, the single-process determinism proof) is in git
history of `tickets/implement/4-bench-gate-reference.md`.

# Review focus — decisions made during implementation, flag if you disagree

1. **Per-plan join-eligibility rule.** The ticket's test list read ambiguously ("two spread
   across different nested plans … is not [gated]"); the normative rule stated twice in the
   ticket body is "two or more join nodes in any ONE plan ⇒ ungated", matching the
   mechanism (the quickpick wall-clock budget engages only on 3+ relations within one
   plan). Implemented per-plan: two nested plans carrying one join node each = **gated**.
   Tested with a why-comment in `bench-gate.spec.ts`.
2. **`validateAcceptAfterPass` skip protection.** Not in the original ticket: with
   `@quereus/store` dist unbuilt, every store row skips under `--accept`, and a naive
   accept would rewrite `store.json` to empty — silently erasing all expectations. Accept
   now refuses when any benchmark failed, or when a previously-recorded benchmark skipped
   this run (message names the benchmark, skip reason, and fix). LevelDB rows never have
   reference entries, so they skip freely. Tested.
3. **`runCountersPass` param typed `() => unknown | Promise<unknown>`** (not `object`) so
   its null/typeof validation survives strict checkJs — behavior unchanged, shared now by
   `child.mjs` and `gate.mjs` from `bench/lib/counters.mjs`.
4. **Accept skips a suite with nothing measured AND no previous file** (nothing to record);
   an empty measurement against an *existing* previous file still records the removal —
   deliberate, so deleting all of a suite's counter declarations shows up in the diff.
5. **Reference provenance commit predates the harness edits.** The initial
   `bench/reference/*.json` were generated with `--allow-dirty` mid-ticket; the recorded
   commit (`a8999c107`) predates the gate code itself. The dirt was harness-only (no
   engine `src/` changes), so the counts are that commit's counts — but a reviewer may
   prefer to re-run `bench:accept` post-merge for clean provenance.

# Known gaps / tripwires (indexed here, homes at the code sites)

- `NOTE:` at the pass loop in `gate.mjs`: the single-process premise (verified 56/56
  byte-identical vs the forked run today; a counter block differing between `yarn bench`
  and `yarn bench:gate` is the signal a benchmark started leaking state).
- `NOTE:` same site: fixture-population is the dominant cost (~42 s total); sharing one
  populated counting database across read-only execution workloads is the lever if that
  must drop.
- Cross-machine counter identity is still an assumption — no second machine has run the
  gate yet. The multi-join exclusion removes the one known mechanism
  (`bug-join-order-depends-on-wall-clock`, backlog); the first CI-or-colleague run is the
  real test.
- Two concurrent accepts are last-writer-wins (comment at the write site); the atomic
  rename only protects readers.

# How to exercise it

```
yarn workspace @quereus/quereus bench:gate                 # ~42 s, expect exit 0
yarn workspace @quereus/quereus bench:gate --filter planner  # ~0 s, planner only
yarn workspace @quereus/quereus bench:gate --json          # object on stdout, report on stderr
yarn workspace @quereus/quereus bench:accept --reason "x"  # refuses on dirty tree without --allow-dirty
```

A quick adversarial probe: flip any planner cost comparison, rebuild, run
`bench:gate --filter planner` — the diff should name the exact node-type counts that moved.
