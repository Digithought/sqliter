# What was broken

`new` and `old` are not reserved words, so `create table "new" (…)` is legal — and a
bare `new.<col>` / `old.<col>` inside a CHECK, DEFAULT, generated body, or a result
column's `with inverse (…)` clause names a **written row**, never a catalog table. The
column-rename walker decided which meaning applied with a boolean chosen at the walk's
entry point, but the answer is a property of the **position in the tree**, and the domain
has three values, not two. Three verified corruption arms (all reproduced at `4f1b724c`):

- **Arm A** — `alter table "new" rename column v to w` rewrote every OTHER table's
  `new.v` (CHECK / DEFAULT / generated), leaving those tables permanently unwritable;
  `alter table "new" drop column v` was false-refused by the same qualifiers.
- **Arm B** — a `with inverse` expression's `new.<output-col>` refs (which name the
  enclosing select's output row) were treated as references to a table called `new` by
  both walkers: corrupted by `rename column` AND `rename to`, and they put a table
  called `new` into the drop-guard reach (false refusal of `drop table "new"`). This
  also falsified the root-only NOTE in `object-dependency-closure.ts`.
- **Arm C** — the depth-blind output-name-shift pass (`renameNewQualifiedRefs`) reached
  into a NESTED select's own `with inverse` clause and moved `new.` refs that belong to
  the nested select's outputs.

# What was done

- `RowImageContext = 'none' | 'own' | 'foreign'` added to `rename/shared.ts`; the column
  walker's state carries it and the four public entry points (`renameColumnInAst`,
  `renameColumnInCheckExpression`, `columnReferencedInAst`,
  `columnReferencedInCheckExpression`) take it as a **required** parameter inserted after
  `targetKey` (compile error at every call site was the point). The three collection
  helpers keep their signatures and hardcode their documented mode (checks `'own'`,
  column expressions `'own'`, index predicates `'none'`), so `@quereus/quereus-store`
  needed no change and got none.
- Unbound-bare decision (`matchesRowImage`, three-way): `'own'` matches, `'foreign'`
  ignores (neither rewritten nor resolved as a table), `'none'` falls through to catalog
  resolution as before. In-scope bindings and schema qualifiers still decide first.
- Both walkers force the suppression over `with inverse` **and** `with defaults`
  expression subtrees, save/restore, unconditionally — so reached view bodies
  self-suppress and `reachableObjects`' root-only `rootOpts` stays correct for the new
  reason (NOTE rewritten; reached-body case now pinned by 41.10.4 §16). The table walker
  keeps its boolean (`false`→'none', `true`→'foreign' — it never matches, only
  suppresses); the mapping is documented on `TableRenameOpts`.
- `renameNewQualifiedRefs` skips `inverse` keys during its depth-blind walk (`inverse`
  is a property of result columns only, and the walk's roots are the outer clause's
  exprs, so every in-walk `inverse` belongs to a nested select). Correlated `new.` refs
  in ordinary subqueries are still reached.
- Per-site modes threaded exactly per the ticket's table (alter-table emit, differ
  inverse reconcile, assertion/MV helpers, drop guards, republication, both probe call
  sites). The one non-constant site (`columnProbe`) computes
  `reached.ownerKey === undefined ? (seeded ? 'own' : 'foreign') : 'none'` with the rule
  stated in prose at the site.

# Validation performed

- `yarn build`, `yarn lint` (includes the test-file tsc pass), `yarn test` — all green
  (quereus: 8918 passing / 0 failing), **and `yarn test:store`** (8910 passing / 0
  failing — the persisted-DDL round trip the ticket flagged as the riskiest arm).
- New class-level guard `test/schema/row-image-context-matrix.spec.ts`: 9 sites
  {own/other CHECK, own DEFAULT, own generated, other DEFAULT/generated, partial-index
  predicate on "new", assertion body, plain view body, view-body `with inverse`} × 4
  spellings {bare `new.`, bare `old.`, FROM-bound `"new".`, schema-qualified
  `main."new".`} — 36 cells, each asserting rewrite/no-rewrite and exact result text.
- End-to-end pins: 41.3 §62 (Arm A no-ops for CHECK/DEFAULT + `old.` + four controls
  including own-table `new.` on a table itself named "new"), §63 (Arm B view under both
  verbs + the seeded-CHECK-one-level-in shape), §64 (Arm C nested inverse, including the
  actual write-through: outer `new.v`→`new.w` followed the output shift, inner stayed);
  41.10.2 §37 (drop column of "new" allowed vs foreign row image, still refused vs
  genuine `"new".v` subquery ref); 41.10.4 §16 (drop table "new" allowed through a
  reached `with inverse` body; the chain's real source still protected).
- Pre-test runtime sanity: 13 ad-hoc scenarios against the built engine (all arms +
  controls) passed before the suites ran.

# Reviewer notes / known gaps

- **`with defaults` is documented self-contained but NOT enforced at CREATE VIEW** —
  probe: `create view V9 as select id, a from T9 with defaults (b = new.a + 1)` is
  accepted. Per the ticket's contingency, defaults entry exprs get the same subtree
  suppression as inverse exprs (such a ref could never plan as a table reference
  anyway), and docs/sql-select.md § Insert defaults now says so. If a reviewer thinks
  create-time rejection is the better fix, that is a separate (new) ticket — the
  suppression here is correct either way.
- **Generated-body Arm A has no sqllogic case** — 41.3 §62 covers CHECK and DEFAULT.
  The other-table generated body takes the *same* call as the other-table DEFAULT
  (`rewriteOtherTableColumnExpressions`, one loop), and the matrix spec pins both
  own/other generated cells at walker level with the exact emit-layer modes, so
  coverage is by shared code path rather than by an end-to-end row.
- The matrix spec drives the walker entry points with the modes the emit layer passes;
  it does not execute ALTER statements. The sqllogic sections are the end-to-end pins.
- `isQualifierReboundAboveSeed` is now formally redundant at its only call site (the
  caller reaches it only when nothing in scope binds the qualifier); kept and documented
  as a belt-and-braces guard for future call sites.
- The differ's inverse reconcile mirrors the forward modes but gained no differ-specific
  new test; the existing differ suites and the store round trip (which re-parses and
  re-diffs persisted DDL) are what cover it.
- Two sibling tickets touch `rename/column-rename.ts`
  (`rename-column-scope-walk-blind-to-aliased-sources`,
  `rename-preserves-the-meaning-of-every-name-in-a-body`); per the ticket, the
  positional signatures were deliberately NOT bundled into an options object this cycle
  to minimize conflict.
