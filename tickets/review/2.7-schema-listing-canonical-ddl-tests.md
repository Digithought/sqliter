# Schema-listing canonical DDL: catalog.ts fix + schema() TVF round-trip tests

Continuation of `schema-listing-canonical-ddl-followup` (ticket file already deleted; prior
session). Two pieces of work, both done and verified this session.

## 1. Second UNIQUE-lift bug, same root cause, different call site — fixed

`packages/quereus/src/func/builtins/schema.ts`'s `schema()` TVF had a bug (fixed in a prior
session): rendering the DDL for a store-backed table's exposed implicit unique index without
lifting `unique: true` onto the descriptor first, so the persisted DDL was missing `UNIQUE`.

This session found the identical bug on a second call site: `collectSchemaCatalog` in
`packages/quereus/src/schema/catalog.ts` (~line 269-272) called
`indexSchemaToCatalog(desc, tableSchema, db, true)` with the raw `SyntheticExposedIndex`
descriptor straight through — same missing lift, same silently-wrong `CREATE INDEX` (no
`UNIQUE`) for the STORE-persistence side of the catalog.

Fix: moved the lift into `catalog.ts` (it owns the `SyntheticExposedIndex` type) as an exported
function `syntheticExposedIndexToIndexSchema(desc): IndexSchema`, right after the
`SyntheticExposedIndex` interface (~line 866-876). `collectSchemaCatalog`'s call site now goes
through it. `schema.ts` no longer defines its own copy — it imports the shared one from
`../../schema/catalog.js`.

Swept the whole test tree (21 `.sqllogic` files + 10 `.spec.ts` files matching `schema()`,
plus `quoomb-cli`'s dot-commands/repl) for any assertion pinning the OLD hand-rolled DDL text on
a `type = 'table'` row — nothing else needed updating. Every other file selects `name`/`tags`/
`count(*)` or uses `.toContain(...)` substring checks, none pin exact canonical DDL text.

## 2. Two new round-trip tests, through the schema() TVF specifically

New file `packages/quereus/test/schema-func-ddl-roundtrip.spec.ts`. Existing
`table-ddl-round-trip.spec.ts` / `index-ddl-roundtrip.spec.ts` pin `generateTableDDL` /
`generateIndexDDL` directly; this file's job is different — confirm the `schema()` TVF calls
those generators correctly (not re-deriving anything) by going through the TVF itself.

**Test 1** — table with PK, NOT NULL, DEFAULT, COLLATE, CHECK, UNIQUE, FOREIGN KEY, and tags:
- creates `parent`/`child` in a source DB, reads `table_info`/`check_constraint_info`/
  `unique_constraint_info`/`foreign_key_info`/tags, and `schema().sql` for both tables
- execs both DDL strings into a fresh DB, re-reads the same five views, asserts deep-equal
  against the originals
- **behavioral DEFAULT check**: inserts a row into the reconstructed `child` omitting the
  defaulted columns, asserts the DEFAULT values (`'anon'` / `'active'`) actually land. This
  replaces the ticket draft's `table_info().dflt_value` deep-equal for those columns —
  `dflt_value` is built as `column.defaultValue?.toString()`, but `defaultValue` is an AST
  `Expression`, not a raw value, so it degrades to `"[object Object]"` on both sides (a
  pre-existing, unrelated quirk — the test drops `dflt_value` from the compared columns via a
  `withoutDefaultValue` helper rather than asserting on that meaningless string)
- asserts `schema().sql` on the reconstructed table re-emits byte-identical to the original
  (fixed-point check)
- **caught one real bug while drafting**: the first version inserted into the reconstructed
  `child` without first inserting a row into `parent`, so the FK constraint (`parent_id`
  referencing `parent.id`) rejected the insert. Fixed by inserting a `parent` row before the
  behavioral DEFAULT check.

**Test 2** — unique partial index with tags:
- creates `widgets` + a `unique index ... where status = 'active' with tags (...)`, reads
  `index_info`/`unique_constraint_info`/tags/`schema().sql`
- execs the index DDL into a fresh DB (table pre-created first — memory module requires the
  table to exist before a secondary index connects, same pattern
  `index-ddl-roundtrip.spec.ts`'s `buildSource` tests use), re-reads, deep-equal, fixed-point
  check on re-emitted DDL

Both tests pass in isolation and as part of the full suite.

## Known gaps / what a reviewer should look at

- The new spec's table test only covers ONE shape of default (`text` literal `DEFAULT 'anon'` /
  `'active'`) and one FK shape (single-column, no `ON DELETE`/`ON UPDATE` action). It does not
  exercise composite FKs, expression defaults, or FK actions round-tripping through
  `schema().sql` — those are untested by this ticket. If that matters, it's a `debt-` ticket for
  a future session, not something blocking this one (the ticket only asked for "the two missing
  round-trip tests").
- The `dflt_value` / AST-stringify quirk in `table_info()` (`packages/quereus/src/func/builtins/
  schema.ts` ~line 269, `column.defaultValue?.toString() || null`) is real, pre-existing, and
  NOT fixed here — the ticket draft flagged it explicitly as a known weak spot to route around,
  not silently rely on. Worth a `NOTE:` at that site or a follow-up ticket if `table_info()`'s
  `dflt_value` column is ever meant to be a real default-value comparison surface; out of scope
  for this ticket, which only needed the round-trip test to not falsely rely on it.
