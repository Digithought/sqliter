# `undefined` is the only spelling of "unknown" — implemented

`TableSchema.estimatedRows` is deleted. `catalogRowCount(table)` is now
`table.statistics?.rowCount`: `undefined` means nobody knows, a number (including a
real 0 from `ANALYZE` of an empty table) means measured. All seven writers of the fake
zero are gone — the ticket listed four; three more were found in
`runtime/emit/materialized-view-helpers.ts` (backing-table build, normalize probe,
adopt) and one in `sample-plugins/json-table`. The public `TableSchema` type shrinks by
one field — source-breaking for third-party constructors, accepted per AGENTS.md
(backwards compat not yet a concern).

## The behavior change that was the point

`CatalogStatsProvider.tableRows` now actually reaches its `NaiveStatsProvider`
fallback (default 1000) for never-analyzed tables — the path was dead before because
`catalogRowCount` never returned `undefined`. `NaiveStatsProvider.tableRows` itself no
longer reads the schema and always answers its configured default.

## Consumers audited (verified, not edited)

- `rule-grow-retrieve` ~369/~800 (`|| stats || 1000`) and `rule-select-access-path`
  ~263 (`|| undefined`), ~1232 (`|| 1000`): `0 → undefined` is invisible through `||`;
  net result identical (1000 / undefined).
- `rule-lateral-top1-asof` ~261 (`?? undefined`): now genuinely `undefined`; the store
  fills its live count in (`sizeRequestFromLiveCount` fires on `undefined` exactly as
  it did on the rule's old `|| undefined` spelling).
- CTE-caching gates (`estimatesRows` default 1000, `isExpensive > 10000`,
  `getCacheThreshold` floor 1000): the 0→1000 jump flips none of them.
- `DeltaExecutor.getRowCount` (assertions + watchers): previously ALWAYS returned the
  fake 0, which its `rowCount > 0` guard discarded — the per-binding→global demotion
  was dead code. Wired through `catalogRowCount`, so it now works for analyzed tables.
  This is a behavior *activation*, not just a spelling fix.
- `lens-prover` fingerprint `cardinalityBand`: un-analyzed basis now bands as
  `'unknown'` instead of `'empty'`. Existing lens acknowledgments recorded against the
  old `'empty'` band on never-analyzed tables will re-prompt once. Judged acceptable
  (band was a lie); flag if lens ack churn matters.
- `database-auto-analyze` `?? 0` sites: never-analyzed and analyzed-empty deliberately
  stay collapsed (both want a prompt first/next ANALYZE) — NOTEs at both sites say why.
- `aggregateRowsFrom` keeps its `0 → 0` arm (0 rows in ⇒ 0 groups out); its comment now
  justifies it on those grounds alone, since the unknown sentinel no longer exists.

## Downstream defects the fake zero was masking (fixed here, same root cause)

1. **Fan-out cross-cluster guard was un-refusable.** `crossGuardsPass` documents
   "unknown estimates refuse to cluster", but un-analyzed tables reported 0 and the
   product-cap always passed with zero information. Now the guard actually refuses;
   the fanout specs' fixtures run `analyze` so the shapes they pin stay reachable.
2. **MV maintenance residual↔rebuild crossover ran on fiction, and honest numbers
   exposed a worse fiction.** `residualCostPerGroup` modeled a key-filtered residual
   as touching only its group's rows; with no index on the binding key each run
   actually scans the whole source. With honest 1000-row estimates the demotion to a
   single rebuild stopped firing and a 100-row statement paid ~100 full scans — the
   perf sentinel caught it at 22.9× (bound 12×, historical ~3×; baseline HEAD measured
   3.9×, regressed tree 20×, verified via A/B repro). Root fix: `compileResidual` now
   returns the optimized residual plan's `getTotalCost()` and the arm builders stamp
   it into `MaintenanceSourceStats.residualExecutionCost`, so the crossover judges the
   residual by what it actually does (seek when indexed, scan when not). Plus
   `MIN_DEGRADE_DISTINCT_KEYS = 3`: a 1–2-key statement never demotes to
   `'replace-all'` (whole-backing write amplification the formulas don't carry; also
   what keeps the store's adopt-sentinel semantics — a rebuild on a 1-row insert
   erased the planted sentinel and failed `mv-rehydrate-adopt.spec.ts`). After the
   fix: sentinel spec green, perf sentinel green (~4.7× vs 3.9× baseline).
3. **MV adopt now carries measured statistics forward.** `adoptMaterializedView` used
   to stamp `estimatedRows: preExisting.estimatedRows ?? 0` (always 0); it now carries
   `preExisting.statistics` (when present) onto the re-stamped backing schema — the
   only remaining vehicle for the row knowledge the old line intended to preserve.

## Known gaps / notes for the reviewer

- The compiled-residual cost inherits the `||`-collapse at `createSeqScan`
  (`estimatedRows || 1000`), so a measured-empty source's residual still prices as a
  1000-row scan — conservative direction (demotes early on wide statements over tiny
  tables), covered by the pre-existing NOTE in `table-cardinality.ts`.
- `MIN_DEGRADE_DISTINCT_KEYS = 3` is a judgment constant, documented at the site; the
  principled alternative (charging `'replace-all'` its per-backing-row write cost)
  needs a backing-size stat that doesn't exist yet.
- Lens acknowledgment band churn ('empty' → 'unknown') noted above.
- Plan churn beyond the goldens is possible for downstream apps comparing un-analyzed
  tables against constants — the ticket's stated intent.
