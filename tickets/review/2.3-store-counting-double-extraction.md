# What changed

`packages/quereus-store/src/testing/kv-counting-store.ts` is a new file exporting:

- **`DelegatingKVStore`** — forwards every `KVStore` method to a wrapped `inner: KVStore`;
  the common base every test double in `test/kv-store-doubles.ts` already extended.
  Moved here (was previously defined locally in `test/kv-store-doubles.ts`) and
  re-exported from there so `batch-point-read.spec.ts`'s existing
  `import { DelegatingKVStore } from './kv-store-doubles.js'` keeps working unchanged.
- **`CountingKVStore`** — the one shared counting double, replacing four
  near-identical hand-rolled copies (three by inheriting `InMemoryKVStore`, one by
  delegation). Exposes `iterateEntryCount`, `getCount`, `getManyCalls`,
  `getManyKeyCount` (all public mutable fields — several call sites zero them
  directly between assertions, e.g. `store.iterateEntryCount = 0`) and a `reset()`
  that zeroes all four.
- **`createCountingProvider(countedStores, scope?)`** — a `KVStoreProvider` factory
  parameterized by `scope: 'data' | 'all'` (default `'data'`), replacing three
  near-identical local copies. `'data'` counts only each table's data store (index/
  stats/catalog stay plain, uncounted `InMemoryKVStore`s in an internal map the
  caller never sees) — used by `pushdown.spec.ts` and `key-set-seek-store.spec.ts`.
  `'all'` counts every store the provider hands out into the caller's own map —
  used by `index-scan-batching.spec.ts`, which reads index-store counters back out
  (`stores.get('main.t_idx_ix_v')`).

Both are exported from `src/testing/index.ts` (the `@quereus/store/testing` entry
point) alongside the existing conformance batteries.

## The one subtlety (already resolved before this ticket reached implement)

`CountingKVStore.getMany` must route through `defaultGetMany(this, keys)`, **not**
`this.inner.getMany(keys)`. The latter looks like the obvious delegating
implementation but silently breaks `getCount` for every existing batched-read
assertion — see the doc comment on `CountingKVStore` in
`kv-counting-store.ts` for the full mechanism (virtual dispatch through `this`
vs. a genuinely separate `inner` object). This was identified and written up during
a prior implement pass on this same ticket slug; this pass implemented it exactly as
specified and it holds — see test results below.
