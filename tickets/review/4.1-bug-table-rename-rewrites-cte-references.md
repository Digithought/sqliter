# Table rename is now scope-aware (was: rewrote CTE/alias-bound names and `new.`/`old.` row images)

## What was done

`visitTableRename` (a depth-blind name match) was replaced by a scope-aware
**table-reference walk** in the new `packages/quereus/src/schema/rename/table-rename.ts`.
The walk reports every REAL table reference to a sink over **one traversal**;
`renameTableInAst` (rewrite sink) and `tableReferencedInAst` (probe sink with
early-out) are both expressed over it, so the DROP guard refuses exactly what a
rename would rewrite — pinned by a test, not just a comment.

Scope rules implemented (ticket's design, faithfully):

- **WITH frames** register CTE names in planner visibility order (a
  `with recursive` member's name before its body, a non-recursive member's
  after — mirrors `pushWithFrame` / `buildCommonTableExpr`). A FROM source
  naming an in-scope CTE (unqualified only) is not a reference.
- **FROM frames** bind qualifiers: an unaliased real source binds its name to
  the source's identity (schema-as-written + name); aliases, CTE sources,
  subquery/function sources bind to "not a table". A qualified column ref
  resolves innermost-first; bound-to-non-table → skipped; unbound → direct
  reference (the CHECK/index self-qualifier case). Schema-qualified
  `main.zap.k` bypasses the frames entirely (never a CTE/alias/row image).
- **DML targets** mirror `resolveCteTarget`: an unqualified target naming a
  member of the statement's OWN leading WITH is the CTE (skipped);
  schema-qualified never is. Enclosing WITHs deliberately do NOT shadow a
  write target, matching the planner.
- **Row image** (`rowImageContext` on `TableRenameOpts`): threaded from
  `renameTableInCheckConstraints`, `renameTableInColumnExpressions`, the
  equivalent per-check loop in `alter-table.ts` (`rewriteTableForTableRename`),
  and the differ's inverse CHECK reconcile — NOT from
  `renameTableInIndexPredicates` (deliberate asymmetry: a predicate has no
  written-row context). Suppression is scope-aware: only an UNBOUND bare
  `new.`/`old.` qualifier is a row image; a subquery `from "new"` rebinds it.

The size-NOTE's tripwire condition ("if the table walker grows its own
ScopeFrame, split along those three seams") tripped, so the split was done:
`rename-rewriter.ts` is now a barrel (35 lines) over `rename/table-rename.ts`
(~560), `rename/column-rename.ts` (~1050, moved verbatim),
`rename/self-qualifier-strip.ts` (~295, moved verbatim), `rename/shared.ts`
(~50). No import site changed.

## Behavior changes beyond the ticket's literal list (flag for review)

- **Source-schema-aware qualifier match.** A qualified column ref bound by an
  unaliased FROM source now matches by the SOURCE's identity: renaming
  `main.zap` no longer rewrites `zap.k` in `select zap.k from other_schema.zap`
  (the old walker did, breaking the ref). Strictly more correct; pinned in the
  spec ("reference through a table in another schema").
- **Inline subquery DML targets.** `update (select … from zap) as v …`: the
  parser fills `stmt.table` with a synthetic placeholder equal to the alias.
  The old walker rewrote the placeholder (corrupting it when the alias matched
  the renamed name) and never descended the body; the new walk skips the
  placeholder and descends `targetSource`. Same defect family (a bound name
  that is not a table reference); pinned in the spec's equivalence loop only
  indirectly — no dedicated sqllogic (a stored AST with an inline DML target is
  hard to reach through DDL).

## Known gaps / accepted mirrors

- **Set-op legs** are visited inside the first leg's FROM frame (exactly where
  the column walker visits them). A qualifier in leg 2 unbound by its own FROM
  could in principle resolve against leg 1's frame; that SQL is invalid anyway
  and the placement mirrors the existing column walker rather than inventing a
  second convention.
- **Renaming a table TO the name `new`** converts a rewritten self-qualifier
  (`x.a` → `new.a`) into something later walks — and the CHECK planner itself —
  read as a row image. Inherent ambiguity of naming a table `new`; pre-existing
  hazard, unchanged by this ticket (the row-image direction here only governs
  matching the OLD name).
- **sqllogic §46 `v_pos2`** had to drop the three-part `main.zap.k` COLUMN ref:
  the planner does not resolve that spelling in a view body today ("main.zap.k
  isn't a column" at CREATE VIEW). The AST-level rewrite of the three-part ref
  is pinned in the mocha spec instead; the sqllogic keeps the `from main.zap`
  half.
- The differ's COLUMN rewriter remains scope-naive about a subquery-source
  alias equal to a renamed table's name (comment updated at
  `declaredIndexCanonicalBody` to scope the claim to the column verb only).

  - §42 view CTE shadow preserved (view still returns CTE row after rename)

    source — all still rewrite

    still enforces (violating insert rejected)
